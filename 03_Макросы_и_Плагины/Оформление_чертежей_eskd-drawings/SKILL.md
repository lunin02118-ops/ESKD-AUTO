# Оформление чертежей ЕСКД через SolidWorks API

Источник — репозиторий инструментария: `03_Макросы_и_Плагины\Оформление_чертежей_eskd-drawings\`.
Скрипты отработаны на заказе 778 (Кровать, 22.09.2026): 8 деталей из труб 40×20 и 25×25, 3 сварные рамы.

## Что не трогать

- Шаблоны, форматки, рамки, основные надписи — не менять (решение владельца). Форматки брать из
  `D:\Work\_Инструменты_Конструктора\02_Шаблоны_и_Форматки\Основные надписи` через `SetupSheet5`.
- Главный сборочный чертёж изделия владелец делает сам.
- Существующий чертёж не перезаписывать: старый перенести в `_Аннулировано` изделия.

## Порядок

1. SolidWorks запущен, модели изделия открыты (сборка верхнего уровня). `ESKD_DRW_ROOT` = папка `01_3D` изделия.
2. Детали из трубы: `python scripts\tube_drw.py "<часть имени>" ... --final`.
   Без `--final` черновик и снимок ложатся в `ESKD_DRW_SNAP` (по умолчанию временная папка) — сначала посмотри его.
3. Сборки (сварные рамы): `python scripts\asm_drw.py "<часть имени>" ... --final`.
4. Проверка: `python scripts\snap_sheets.py <чертёж.SLDDRW> <префикс>` → JPG каждого листа, затем
   `python scripts\sheet.py out.jpg a.jpg b.jpg ...` — контактный лист. Смотри каждый лист глазами (чек-лист ниже).

## Что делает `tube_drw.py`

- Ось трубы по наибольшему габариту; главный вид — со стороны скоса торцов (срез виден), без скоса — со стороны
  отверстий, без отверстий — на широкую стенку; вид поворачивается осью по горизонтали.
- Разрыв (`IView.InsertBreak3` + `BreakView`) на участках без отверстий и торцевых зон; не помещается на A4 — A3.
- Вид слева — профиль, размеры сечения справочные `*40`, `*20`.
- Размеры: длина по крайним вершинам, углы реза (острый угол у носка), отверстия `N отв. Ø…` и координаты от
  ближнего торца, уступы и язычки на торцах, скругления `R…`. Отверстия противоположной стенки — отдельным видом.
- ТТ через `apply_tt_profile.py` (SWPlus `ТТ`) с профилем «Деталь: Лазерная резка трубы».

## Что делает `asm_drw.py`

- Главный вид в плоскости рамы (нормаль — наименьший габарит), вид сверху под ним, в свободном поле слева
  от основной надписи; колонка над основной надписью остаётся под ТТ.
- Размеры по точной геометрии видимых рёбер (не выбором точкой — точка цепляет касательное ребро скругления трубы,
  выходит 944,6 вместо 950): габариты, положение внутренних элементов от кромки рамы, толщина рамы `*`.
- Лист SP1 (`SP-1.slddrt`) со спецификацией: BOM по `SpecEditor_sp.sldbomtbt`, разделы «Документация»
  (`<обозначение> СБ` Сборочный чертеж) и «Детали» — заголовки подчёркнуты и по центру, как пишет SpecEditor;
  записи по обозначению, позиции по порядку строк.
- Позиции (`InsertBOMBalloon2`, полка) — по одной на запись, выноска к ребру ближайшего экземпляра; правая половина —
  колонкой справа, левая — строкой над видом; выноски не пересекают ТТ.
- ТТ по сварке и покрытию. Цвет покрытия — «по заказу»: уточни у конструктора.

## Грабли SolidWorks API (проверено)

- `NewDocument` с шаблоном чертежа показывает окно «Формат листа/Размер» — `scripts\ok_sheet_dialog.ps1` жмёт ОК.
- Первый вставленный вид сбивает масштаб листа (автомасштаб) — `SetScale` после вставки, `UseSheetScale = 1`.
- `IView.Position` — только `VARIANT(VT_ARRAY|VT_R8)`, кортеж молча не работает; Position — точка привязки,
  не центр контура (`place()` учитывает смещение). Проекционные виды едут за родителем — ставь родителя первым.
- `ModelToViewTransform` содержит масштаб вида — нормаль окружности нормируй.
- Вершины из `GetVisibleEntities2(..., Vertex)` в другой системе координат — бери концы видимых рёбер.
- В виде сборки рёбра компонента даны в системе детали: преобразование — `Transform2` компонента сборки
  с тем же именем (у компонента вида его нет).
- Положение линий разрыва `InsertBreak3` — относительно `IView.Position`.
- У диаметра знак Ø хранится в префиксе размера: `SetText(1, "2 отв. " + GetText(1))`, иначе Ø пропадёт.
- Вставленная строка таблицы наследует формат соседней (подчёркивание заголовка) — сбрасывай явно.
- Пакетная работа: `sw.CommandInProgress = True` на время пакета, иначе SolidWorks молча падает.
- Путь с кириллицей в скрипте через stdin Bash портится — запускай файлы `.py`.

## Чек-лист проверки листа (ЕСКД)

- Формат и масштаб в основной надписи совпадают с листом; обозначение сборки с «СБ», наименование верное.
- Виды внутри поля: ниже графы вверху слева, не на основной надписи и не на ТТ.
- Размеры не пересекаются с видами и друг с другом; у сборки — габариты, присоединительные, положение элементов.
- Справочные размеры со `*` есть, раз в ТТ есть пункт «*Размеры для справок».
- Позиции совпадают с номерами спецификации, у каждой записи — одна позиция, выноски не пересекаются.
- ТТ не шире 185 мм, пункты пронумерованы, текст не выходит за рамку.
- Наименование модели и длина детали согласованы (в 778 «Перемычка 940» при длине 950 — сообщить, не править).
