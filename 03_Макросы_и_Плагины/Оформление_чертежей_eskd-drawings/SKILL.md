# Оформление чертежей ЕСКД в SolidWorks

Источник — репозиторий инструментария: `03_Макросы_и_Плагины\Оформление_чертежей_eskd-drawings\`.
Скрипты отработаны на заказе 778 (Кровать, 22.09.2026): 8 деталей из труб 40×20 и 25×25, 3 сварные рамы,
групповой чертёж листового кронштейна на 4 исполнения.

## Главное правило: сначала макрос, потом API

У конструктора есть готовые макросы SW+ (`D:\Work\_Инструменты_Конструктора\03_Макросы_и_Плагины\Макросы_SW_ZTool\SWPlusMacro_v_2018_SP0.0\`),
и изделие ведётся ими. Чертёж, сделанный «своим» способом, ломает привычный порядок: спецификация, собранная
руками, отличается от SpecEditor; формат, выставленный скриптом, не совпадает с тем, что пишет в основную надпись
DProp. Поэтому:

| Задача | Чем делать |
|---|---|
| Спецификация на листе сборочного чертежа | макрос **SpecEditor** (`scripts\spec_one.ps1`) |
| Формат листа, ориентация, основная надпись, «Листов N» | макрос **DProp → Мастер форматов** (`scripts\fmt_portrait.ps1`) |
| Свойства модели (обозначение, наименование, материал) | макрос **MProp** или надстройка ЕСКД, **и только с разрешения владельца** |
| Виды, размеры, позиции, швы, ТТ | API (скрипты ниже) |

Свойства моделей заказа менять нельзя: спецификация Кровати собирается из них, и правка разваливает
позиции (замечание владельца 22.09.2026). Переименование файла допустимо, правка свойств — нет.

## Что не трогать

- Шаблоны, форматки, рамки, основные надписи. Форматки берутся из
  `D:\Work\_Инструменты_Конструктора\02_Шаблоны_и_Форматки\Основные надписи` (`SetupSheet5`).
- Главный сборочный чертёж изделия владелец ведёт сам.
- Существующий чертёж не перезаписывать: старый — в `_Аннулировано` изделия (удаляет владелец).

## Порядок

1. SolidWorks запущен, изделие открыто. `ESKD_DRW_ROOT` = папка `01_3D` изделия.
2. Детали из трубы: `python scripts\tube_drw.py "<часть имени>" ... --final`.
3. Сборочный чертёж: `python scripts\asm_drw.py "<часть имени>" --final` — лист с видами.
4. Формат листа под содержимое: `powershell scripts\fmt_portrait.ps1 "<чертёж.SLDDRW>"`
   (А3 книжный для узких рам; альбомный оставляют как есть).
5. Спецификация: `powershell scripts\spec_one.ps1 "<чертёж.SLDDRW>"` — SpecEditor создаёт лист `SP1`.
6. Сварная сборка: `python scripts\asm_weld_drw.py "<часть имени>" --save` — перестраивает первый лист
   на уже готовом формате: виды, размеры, позиции, швы по ГОСТ 2.312, таблица швов, ТТ сварки.
7. Листовая деталь с исполнениями: `python scripts\sm_group_drw.py --final` (групповой чертёж по ГОСТ 2.113;
   скрипт заточен под 778 — правится под деталь: `PART`, `CFG`, `ROWS`, ТТ).
8. Проверка: `python scripts\snap_sheets.py <чертёж.SLDDRW> <префикс>` → JPG листов,
   `python scripts\sheet.py out.jpg a.jpg b.jpg` — контактный лист. Смотреть каждый лист глазами (чек-лист ниже).

## Как водить макросы SW+ из скрипта

Формы SW+ — модальные VBA-UserForm, у них нет headless-входа (у MProp есть `MProp_run.main_reload`,
у SpecEditor и DProp — нет). Поэтому форма запускается и по ней «щёлкают» сообщениями Windows:
мышь владельца при этом не двигается (`scripts\macro_ui.py`).

- Запуск: `sw.RunMacro2(путь, модуль, процедура, 0, 0)` — **опция 0**. Опция 1 (выгрузить после запуска)
  убивает немодальную форму сразу после показа.
- `RunMacro2` синхронный: пока форма открыта, вызов не возвращается — запускать в фоновом job'е
  (см. `fmt_portrait.ps1`) или сразу щёлкать из другого процесса (`spec_one.ps1`).
- Окно формы — класс `ThunderDFrame`; снимок — `PrintWindow(hwnd, hdc, 2)`, щелчок — `PostMessage`.
- Элементы MSForms «безоконные», но **рамка (Frame) — отдельное дочернее окно**: щелчок надо слать
  в самое глубокое дочернее окно под точкой, иначе радиокнопки внутри рамки не нажимаются.
- Координаты кнопок (проверено 22.09.2026): SpecEditor «Создать» (470, 305); DProp «Изменить основную
  надпись» (486, 85), «Закрыть» (537, 185); Мастер форматов «Книжная» (36, 137), «Ok» (313, 147).
- SpecEditor берёт сборку из первого вида листа; лист `SP1` перед перезапуском удаляется (`run_macro.py --drop-sheet SP1`).
- DProp считает листы по именам `DRW1`, `DRW2`, … — именуй листы так.

## Сварные швы (ГОСТ 2.312)

- Обозначение — заметка с полкой: `INote.SetBalloon(10, 0)` (подчёркивание = полка),
  `SetLeader3(1, 0, False, False, False, False)` (прямая выноска), `SetArrowHeadStyleAtIndex(0, 8)`
  (половинная стрелка).
- Знак «по замкнутому контуру» API не наносит (`AllAround` у заметки игнорируется, эскизная окружность
  не видна при выключенном отображении эскизов) — символ «○» дописывается в текст (З-36).
- Одинаковые швы имеют один номер (ГОСТ 2.312 п. 8): полное обозначение — у одного шва, у остальных
  только номер; если швов больше шести, номер ставится один раз.
- Таблица швов: «№ шва | Обозначение шва по ГОСТ 2.312 | Кол.», колонки 15/75/12 мм.
- Швы заказа 778: `ГОСТ 14771-76-С2-УП ○` (стык труб в ус), `ГОСТ 14771-76-Т1-УП-△2 ○` (тавровое
  примыкание). Способ сварки уточняется у владельца (778 — полуавтомат в CO2).

## Грабли SolidWorks API (проверено)

- `NewDocument` с шаблоном чертежа показывает окно «Формат листа/Размер» — `scripts\ok_sheet_dialog.ps1` жмёт ОК.
- Первый вставленный вид сбивает масштаб листа (автомасштаб) — `SetScale` после вставки, `UseSheetScale = 1`.
- `IView.Position` — только `VARIANT(VT_ARRAY|VT_R8)`; Position — точка привязки, не центр контура.
  Проекционные виды двигаются только вдоль оси проекции — сдвигай родителя.
- `ModelToViewTransform` содержит масштаб вида — нормаль окружности нормируй.
- Вершины из `GetVisibleEntities2(..., Vertex)` в другой системе координат — бери концы видимых рёбер.
- В виде сборки рёбра компонента даны в системе детали: преобразование — `Transform2` компонента сборки
  с тем же именем. Общее ребро касания принадлежит только одному компоненту — стыки ищи по габаритам.
- Таблица: метода `InsertTableAnnotation2` нет, есть `IModelDocExtension.InsertGeneralTableAnnotation`;
  вставленная таблица оказывается за листом — положение задавать `SetPosition2`, выбирать только по точке
  (`SelectByID2("", "TABLEANNOTATION", x, y, …)`). Наружный контур ставить основной линией:
  `BorderLineWeight = 1`, `GridLineWeight = 0` (`scripts\fix_tables.py`) (З-35).
- «Листов N» — текст заметки основной надписи, не свойство: лист, добавленный через API, графу не обновляет
  (`scripts\set_total_sheets.py`) (З-34).
- Вид развёртки (`CreateFlatPatternViewFromModelView3`) помечает деталь изменённой — вернуть активную
  конфигурацию и закрыть деталь **без сохранения**.
- Проекционный вид выравнивается по началу координат родителя, а не по геометрии: у детали, смоделированной
  в координатах сборки, он уезжает за рамку — `IView.RemoveAlignment()` и поставить по центру контура.
  Точку вставки брать из `GetOutline` родителя, а не из `Position` (З-41).
- Линия гиба на развёртке — эскиз внутри вида, размер к ней API не ставит: рисуем поверх неё вспомогательную
  линию в эскизе вида (`ConstructionGeometry = True`, координаты = лист минус `IView.Position`) и меряем к ней (З-40).
- Окно «Изменить» при создании размера в эскизе вешает скрипт — `sw.SetUserPreferenceToggle(10, False)`.
- Радиус гиба в параметрах листового металла ≠ радиусам «Ребро-кромка» — в ТТ писать фактические
  (`sm_group_drw.bend_params`) (З-38).
- У диаметра знак Ø хранится в префиксе: `SetText(1, "2 отв. " + GetText(1))`.
- Дуги скруглений контура выглядят как отверстия — отбирай по признаку замкнутой окружности.
- Пакетная работа: `sw.CommandInProgress = True` на время пакета, иначе SolidWorks молча падает.
- Путь с кириллицей через stdin Bash портится — запускай файлы `.py`, созданные редактором.

## Чек-лист проверки листа (ЕСКД)

- Формат и масштаб в основной надписи совпадают с листом; масштаб — из ряда ГОСТ 2.302 (1:1, 1:2, 1:2,5, 1:4, 1:5, 1:10…).
- Обозначение сборочного чертежа с «СБ», наименование верное, «Лист/Листов» заполнены.
- Виды внутри поля: не на основной надписи, не на ТТ, не на таблицах.
- Размеры не пересекаются с видами и друг с другом; у сборки — габариты, присоединительные, положение элементов.
- У детали с косым резом длины обеих сторон (по длинной и по короткой), иначе неясно, по какой стороне резать.
- У листовой детали: на согнутом виде — радиусы гибов и полка «А=», на развёртке — все размеры контура,
  отверстий и положение линий гиба.
- Справочные размеры со `*` есть, раз в ТТ есть пункт «*Размеры для справок».
- Позиции совпадают с номерами спецификации SpecEditor, у каждой записи — одна позиция.
- Сварные швы обозначены, номера совпадают с таблицей швов, способ сварки указан в ТТ.
- ТТ не шире 185 мм, пункты пронумерованы, текст не выходит за рамку.
- Несоответствия модели (зазор в стыке, радиус гиба меньше толщины, имя не по длине) — в журнал замечаний,
  модель править только с разрешения владельца.
