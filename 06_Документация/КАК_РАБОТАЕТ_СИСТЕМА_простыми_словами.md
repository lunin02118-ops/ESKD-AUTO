## 1. Коротко: что это и зачем

Конструктор рисует изделие в SolidWorks. Раньше после этого он вручную заполнял штампы, переписывал материалы,
считал массу, выгружал файлы для лазера и трубореза, делал ведомость в Excel, считал на калькуляторе, сколько
хлыстов трубы нужно, и носил бумаги в цех. На это уходили часы, и везде были ошибки.

Теперь это делает программа. В SolidWorks есть вкладка **«ЕСКД»** с кнопками. Каждая кнопка делает одну рутинную
работу целиком. Человек только принимает решения: что рисовать, что менять, готово ли изделие.

Главная идея: **всё про изделие лежит в одной папке изделия** на сервере — модели, чертежи, файлы для станков,
книга ЛЗК для цеха, журнал изменений, отметка «выдано». Цех берёт всё оттуда же. Ничего никуда не копируется.

## 2. Из чего состоит система

| Часть | Что это простыми словами | Кто пользуется |
|---|---|---|
| **SolidWorks 2025** | программа, в которой рисуют детали, сборки и чертежи | конструкторы |
| **Вкладка «ЕСКД»** (надстройка ЕСКД) | наша программа внутри SolidWorks: кнопки и автоматическое оформление по ГОСТ | конструкторы, куратор, начальник КТО |
| **Макросы SWPlus** (MProp, DProp, SProp, SpecEditor и др.) | 9 кнопок на панели быстрого доступа: редакторы штампа, спецификации, шероховатости, техтребований, печать в PDF | конструкторы |
| **SWTools** | отдельная программа, которая выгружает состав изделия в Excel с картинками деталей. Кнопка «Ведомость ЛЗК» зовёт её сама, без окна | работает сама |
| **Drew** | модуль для оформления чертежей, ставится вместе с инструментарием | конструкторы |
| **Excel** | считает книгу ЛЗК и печатает её листы в PDF | все |
| **Шаблоны и форматки** | шаблоны деталей, сборок, чертежей; основные надписи (штампы); библиотека материалов ГОСТ | работают сами |
| **Окно «Настройка рабочего места»** | установщик: ставит и обновляет всё на компьютере конструктора одной кнопкой | конструкторы (один раз), администратор |
| **Сервер (NAS Synology_TR)** | общий диск, где лежат заказы, база стандартных изделий, инструментарий | все |

## 3. Где что лежит на сервере

Всё на сервере `\\Synology_TR\Конструкторский отдел\`:

```
Конструкторский отдел\
├─ _Заявки\                                  ВСЕ ЗАКАЗЫ — здесь работают конструкторы
│    _Шаблон_заказа\                         пустой заказ — скопировать, чтобы завести новый
│    85-1_Т_Центр соц услуг_Мангыстау\       заказ (см. раздел 4)
│    _Сдано\                                 закрытые заказы
│
└─ _Библиотека проектирования\
     _инструменты_конструктора\              ПРОГРАММА: отсюда её ставят (только чтение)
     _стандартные изделия\                   БАЗА эталонов — стандартные изделия
     _ крепеж и фурнитура\                   библиотека крепежа
```

Плюс **архив `_Архив`** рядом с `_Заявки` на том же диске `Z:` — туда кнопка «Закрыть заказ» складывает сданные
заказы. Отдельного диска архива нет.

В регламенте эти папки называются условно: `00_ИНСТРУМЕНТЫ` = `_инструменты_конструктора`, `02_БАЗА` =
`_стандартные изделия`, `03_ЗАКАЗЫ` = `_Заявки`. Папки `04_ПРОИЗВОДСТВО` (`_Производство`) **больше нет**
(см. раздел 13).

**Кто куда может писать:**

| Папка | Пишут | Только читают |
|---|---|---|
| Инструментарий | администратор (публикует новые версии) | все |
| База стандартных изделий, библиотека | куратор базы | все |
| `_Заявки` | конструкторы, начальник КТО, технолог | цех, склад, начальник производства (права выдаёт сисадмин) |
| Архив `_Архив` | кнопка «Закрыть заказ»; удалять может только начальник КТО | начальник КТО |

**Защита от потери:** сервер каждый час делает снимок всех папок (хранит 48 часовых и 30 суточных). Пропал
или испорчен файл — сисадмин вернёт его из снимка за минуту.

## 4. Папка заказа и папка изделия

### Имя заказа

`<номер>_<код>_<объект>_<город>`, например `85-1_Т_Центр соц услуг_Мангыстау`. Код — `Т`, `Ал`, `Аст` или `ВЭД`.

### Что внутри заказа

```
85-1_Т_Центр соц услуг_Мангыстау\
│  СЗ №85-1.docx                      служебная записка
├─ 01_Исходные данные\                ТЗ, договоры, фото с объекта, переписка, что на согласовании
├─ 02_Металл\                         ИЗДЕЛИЯ ИЗ МЕТАЛЛА — по папке на изделие
│    И01_85T.СМ_Кровать одноместная\
│    И02_…\
├─ 03_Корпус\                         корпусная мебель (bCAD) — кнопки её не трогают
└─ 04_Войлок\
```

### Папка изделия — главное место

`И<номер позиции в служебке>_<шифр>_<наименование>`, например `И01_85T.СМ_Кровать одноместная`.

```
И01_85T.СМ_Кровать одноместная\
   01_3D\                             модели и чертежи SolidWorks; главная сборка «85T.СМ.00.000 Кровать…»
   02_PDF\                            чертежи в PDF + листы участков ЛЗК_<шифр>_<участок>.pdf
   03_ЧПУ\Лазер_Лист\                 DXF развёрток для лазера
   03_ЧПУ\Труборез\                   IGS труб и профиля для трубореза
   04_Сопроводительная документация\  КНИГА ЛЗК  ЛЗК_<шифр>.xlsx, паспорта, сертификаты
   _Аннулировано\                     старые версии файлов — ничего не удаляется, всё сюда
   Изменения.xlsx                     журнал изменений (пишет кнопка «Новая ревизия»)
   _Проверка.txt                      служебный: итог последней проверки
   _Экспорт.txt                       служебный: что выгружено для станков
   _Выдано_<дата>.txt                 ОТМЕТКА «изделие отдано в производство»
```

Файлы с подчёркиванием в начале (`_Проверка.txt`, `_Выдано_…txt`) пишут кнопки для себя. Руками их не трогают
и открывать не нужно — всё, что кнопка хочет сказать человеку, она показывает окном «Замечания» (раздел 7).

### Три состояния изделия

| Состояние | Как узнать | Что можно |
|---|---|---|
| **Черновик** | в папке изделия нет `_Выдано_…txt` | править и перевыгружать сколько угодно |
| **Выдано** | в папке изделия есть `_Выдано_…txt` | менять только через кнопку «Новая ревизия» — с причиной и записью в журнал |
| **Сдано** | заказ лежит в `_Заявки\_Сдано` и в архиве `_Архив` | только читать |

## 5. Путь изделия: от служебки до архива

Пример: заказ 85-1, кровать одноместная, 41 штука.

| № | Шаг | Кто | Как |
|---|---|---|---|
| 1 | Пришла служебка | начальник КТО | кладёт её в папку заказа, ставит задачу в Битрикс24 |
| 2 | Папка заказа | начальник КТО | копирует `_Шаблон_заказа`, называет по правилу |
| 3 | Папка изделия | конструктор | копирует пустую папку изделия, называет `И01_…` |
| 4 | Рисует изделие | конструктор | в SolidWorks. Если изделие похоже на стандартное — берёт эталон из базы и кнопкой **«Сделать независимым»** делает свои копии только тех деталей, которые меняет |
| 5 | Оформление | программа сама | при каждом сохранении заполняет обозначение, наименование, материал, массу, подписи (раздел 6) |
| 6 | Проверка | конструктор | кнопка **«Проверить изделие»**: одно окно с вопросами и тем, что обновится само; итог ГОТОВО, ЗАМЕЧАНИЯ или БРАК, список что исправить |
| 7 | Книга ЛЗК | конструктор | кнопка **«Ведомость ЛЗК»**: отмечает операции каждой детали, вводит количество, срок и цвет — получает книгу ЛЗК (раздел 8) |
| 8 | Файлы для станков | конструктор | кнопка **«Выгрузить в производство»**: PDF чертежей, DXF для лазера, IGS для трубореза |
| 9 | Приёмка | начальник КТО | смотрит конструкцию по отчёту и чертежам |
| 10 | Выдача в цех | конструктор | кнопка **«Готово к производству»**: проверка заново, PDF листов участков, отметка `_Выдано`. Путь к папке — начальнику производства |
| 11 | Цех работает | начальник производства, мастера | открывают папку изделия, печатают листы своего участка |
| 12 | Изменение после выдачи | конструктор | кнопка **«Новая ревизия»** на чертеже: номер изменения, причина, журнал, новые файлы с `_Изм1`; затем снова «Готово к производству» |
| 13 | Закрытие | начальник КТО | после отгрузки кнопка **«Закрыть заказ»**: всё в архив `_Архив`, папка в `_Сдано` |

**Стандартное изделие** (есть в базе, делается без изменений) ещё проще: конструктор ничего не рисует.
Начальник производства сам открывает книгу ЛЗК эталона, вводит количество и срок и печатает листы.

## 6. Что программа делает сама, без кнопок

Каждый раз, когда конструктор нажимает «Сохранить», вкладка ЕСКД тихо заполняет свойства модели, из которых
собираются штамп и спецификация:

- **Обозначение и наименование** — из имени файла. Файл `ПРТИ.468211.102 Стойка.sldprt` → обозначение
  `ПРТИ.468211.102`, наименование «Стойка». Поэтому файлы называют только по правилу и переименовывают только
  через «Сохранить как» в SolidWorks, не в Проводнике.
- **Материал** — берётся из библиотеки ГОСТ: конструктор просто выбирает, например, «Труба 80х80х4,0 ГОСТ 8639-82 /
  В 10 ГОСТ 13663-86», а программа пишет в штамп правильную двухэтажную запись.
- **Масса** — считается сама у каждого исполнения детали (до 100 г — в граммах).
- **Подписи** — фамилия конструктора, «Проверил», организация — только в пустые поля.
- **Исполнения** (конфигурации -01, -02) — каждое получает своё обозначение и массу.

Правила записи совпадают с макросом MProp: если открыть MProp и нажать «ОК», он ничего не поменяет. Ручные
правки программа не затирает. Выключить автоматику можно в окне «Настройки ЕСКД».

## 7. Кнопки вкладки «ЕСКД» — по одной

| Кнопка | Где видна | Что делает одной фразой |
|---|---|---|
| **Настройки ЕСКД** | везде | окно: ваша фамилия, организация, включить или выключить автоматику |
| **Синхронизировать** | деталь, чертёж | сразу обновить свойства открытого документа, не дожидаясь сохранения (в сборке — «Проверить изделие») |
| **Деталь БЧ** | деталь | сделать деталь «безчертёжной» (или обратно) |
| **Сделать независимым** | сборка | взять деталь эталона и сделать из неё свою копию с чертежом и новым номером |
| **Ведомость ЛЗК** | сборка | построить книгу ЛЗК изделия |
| **Проверить изделие** | сборка | проверить всё изделие: одно окно — что обновится само, вопросы, замечания; «Применить и сохранить» — и отчёт |
| **Выгрузить в производство** | деталь, сборка | PDF, DXF, IGS в папки изделия |
| **Новая ревизия** | чертёж, деталь БЧ | оформить изменение уже выданного документа |
| **Готово к производству** | сборка | отдать изделие в цех |
| **Закрыть заказ** | сборка | сдать заказ в архив |
| **Снимок эталона** | меню «Инструменты → ЕСКД» | сохранить версию стандартного изделия перед изменением (для куратора) |
| **Отчёт проверки** | меню «Инструменты → ЕСКД» | открыть последний отчёт проверки |

### Окно «Замечания» — одно на все кнопки

Всё, что кнопка хочет сказать, она показывает одним и тем же окном, а не текстовым файлом:

```
┌ ЕСКД: проверка изделия ─────────────────────────────────────────────┐
│ Итог: ЗАМЕЧАНИЯ                          (жёлтая полоса)            │
│ Изделие ПРТИ.468211.100 · сборка …                                  │
│ Показывать: [✓] ● Критично: 0  [✓] ● Замечания: 3  [✓] ● К сведению: 1│
├────────────┬───────────────────┬──────────────────┬─────────────────┤
│ Уровень    │ Документ          │ Что не так       │ Что сделать     │
│ ЗАМЕЧАНИЕ  │ .102 Стойка       │ нет чертежа      │ Кнопка «Деталь БЧ»│
│ ЗАМЕЧАНИЕ  │ .105 Рама сварная │ нет операций     │ Кнопка «Ведомость ЛЗК»│
│ К СВЕДЕНИЮ │ Строка 4          │ L по модели (*)  │ Проверьте длину │
└────────────┴───────────────────┴──────────────────┴─────────────────┘
                     [Копировать список]  [Закрыть]
```

| Уровень | Цвет | Что значит |
|---|---|---|
| 🔴 **КРИТИЧНО** | красный | в производство нельзя, или кнопка не смогла сделать своё (нет файла детали, нет материала, файл не выгрузился) |
| 🟡 **ЗАМЕЧАНИЕ** | жёлтый | надо доделать — «Готово к производству» не пропустит (нет чертежа, операций, «?» в книге) |
| 🔵 **К СВЕДЕНИЮ** | голубой | не мешает, просто знать (длина трубы измерена по модели, нормы по умолчанию) |

Цвет полосы итога: зелёный — всё хорошо, жёлтый — есть замечания, красный — критично. Флажками можно скрыть
уровень. «Копировать список» — чтобы переслать замечания коллеге.

### Деталь БЧ

Простая деталь без чертежа (пластина, отрезок трубы) записывается в спецификацию одной строкой: наименование,
материал и размер, например «Стойка / Труба 80х80х4,0 / L = 300 мм», в графе «Формат» — «БЧ», масса — в
примечании. Кнопка всё это пишет сама и пересчитывает при каждом сохранении. Нажать ещё раз — деталь снова
становится чертёжной, прежние значения возвращаются.

Где это лежит: в «Наименовании» детали — только название («Стойка»), как у любой детали; материал и размер — в
свойстве «Запись_БЧ». SpecEditor берёт оба и раскладывает по строкам таблицы, ничего не записывая обратно в модель.
Поэтому таблица не ломается, когда детали пересохраняются — при ЛЗК, проверке или обычном сохранении.

### Сделать независимым

Стол из заказа почти как стандартный, но столешница шире. Конструктор берёт эталонную сборку, выделяет в дереве
столешницу и жмёт кнопку. В папке изделия появляется **своя** столешница с чертежом и следующим свободным номером,
сборка переключается на неё. Эталон в базе остаётся нетронутым — программа проверяет это контрольной суммой.
Итог — в окне «Замечания».

### Выгрузить в производство

| Что | Куда | Имя |
|---|---|---|
| PDF каждого чертежа | `02_PDF` | `ПРТИ.468211.102 Стойка.pdf` |
| DXF развёртки листовой детали | `03_ЧПУ\Лазер_Лист` | `…_S3мм_120х450.dxf` — толщина и размер в имени; линии сгиба отдельным слоем |
| IGS детали из трубы или профиля | `03_ЧПУ\Труборез` | `ПРТИ.468211.102 Стойка.igs` |

Выгружается только своё: эталоны, крепёж, покупное не выгружаются. Пока изделие не выдано, файлы молча
перезаписываются. После выдачи выданные файлы не трогаются, новая версия получает суффикс `_Изм1`. Отчёт —
окно «Замечания».

### Проверить изделие

Одна кнопка на всё изделие (решение владельца 23.09.2026). Программа сначала только смотрит и показывает одно окно:
что обновится само (реквизиты, материал, масса, формат), вопросы, на которые отвечаете вы (материал к профилю,
обозначение не по имени файла), замечания и список файлов, которые сохранятся. «Применить и сохранить» — ответы и
сохранение за один раз, второй раз жать Ctrl+S в каждой детали не нужно. Файлы, в которых уже были ваши
несохранённые правки, стоят без галочки — их сохраняете вы. «Отмена» ничего не меняет.

Программа обходит всё изделие и проверяет:

| Что проверяет | Если не так |
|---|---|
| все детали найдены, лежат в заказе, базе или библиотеке | **БРАК** |
| сборка перестраивается без ошибок | **БРАК** |
| у детали есть обозначение, наименование, материал, масса | **БРАК** |
| свойства записаны в модель | замечание: нажмите «Проверить изделие» — окно запишет само |
| у детали есть чертёж или она БЧ | замечание |
| у детали отмечены операции | замечание: «Ведомость ЛЗК» |
| изделие выгружено для станков | замечание: «Выгрузить в производство» |
| книга ЛЗК есть, без «?» и по текущей версии изделия | замечание: «Ведомость ЛЗК» |
| в чертежах нет оборванных размеров | замечание |

**Версия изделия.** Проверка запоминает, в каком виде были файлы изделия, — «версию». Книга ЛЗК и выгрузка
запоминают, по какой версии они сделаны. Если после проверки ничего не меняли, «Ведомость ЛЗК» и «Выгрузить в
производство» ничего не спрашивают. Если меняли — один вопрос: **«Проверить сейчас»** или **«Продолжить как есть»**
(тогда в книге и в выгрузке пометка «не проверено», и «Готово к производству» их не примет). То, что ЛЗК и выгрузка
сохраняют сами (операции, возврат исполнения), изменением не считается. Несохранённые правки версию не меняют, но
проверка напоминает о них замечанием — «Готово к производству» ждёт, пока их сохранят. Порядок: проверка → ЛЗК →
выгрузка → «Готово к производству».

Итог: **ГОТОВО** — можно выдавать; **ЗАМЕЧАНИЯ** — чего-то не хватает, в отчёте написано, какой кнопкой это
сделать; **БРАК** — в производство нельзя. Сама проверка ничего не меняет — пишется только то, что вы примените
в окне; запускать её можно сколько угодно. Итог — в строке состояния, а если записывать нечего — в окне «Замечания». Посмотреть прежний итог ещё раз — пункт «Отчёт проверки» в меню «Инструменты → ЕСКД».

### Новая ревизия

Работает только у **выданного** документа (у черновика кнопка серая — черновик правят свободно). Спрашивает: что
изменено, причину (список по ГОСТ 2.503) и что делать с уже сделанными деталями (использовать, доработать, в брак).
Затем сама: пишет строку в `Изменения.xlsx`, ставит номер изменения в штамп, выгружает новые файлы с `_Изм1` и
только потом убирает старые PDF/DXF/IGS в `_Аннулировано`. Штамп не сохранился — ревизии нет: штамп прежний, строка
журнала помечена «ОТМЕНЕНО». У детали с исполнениями новые файлы выгружаются только для активного исполнения — старые
файлы остальных кнопка назовёт: выгрузите изделие с главной сборки и перенесите названные файлы в `_Аннулировано`
руками. После этого — «Ведомость ЛЗК» (если менялась модель) и снова «Готово к производству».
Если выданную деталь или чертёж поправили и сохранили без ревизии, «Проверить изделие» скажет об этом замечанием.

### Готово к производству

См. раздел 9.

### Закрыть заказ

Когда заказ отгружен. Для каждого изделия собирает комплект — сборку со всеми деталями и чертежами в одной
папке, — копирует весь заказ, сверяет копию с оригиналом по контрольным суммам и только потом переносит в архив
`_Архив\<год>\<заказ>` (рядом с `_Заявки`). Папка заказа уезжает в `_Сдано`, в ней остаётся записка со ссылкой на архив. Если что-то
сорвалось — рабочая папка не трогается, повторный запуск продолжает с места остановки.

### Снимок эталона

Для куратора базы. Перед изменением стандартного изделия кнопка кладёт копию текущей версии в `_Версии\<дата>_Изм<N>`
и пишет в журнал причину и **в каких открытых заказах этот эталон уже выдан** — чтобы знать, кого предупредить.

## 8. Книга ЛЗК — подробно

ЛЗК — лимитно-заборная карта: что, сколько и из чего делать. Раньше это была ведомость на одно изделие, а всё
остальное считали руками. Теперь это **живая книга Excel** на каждое изделие:
`<папка изделия>\04_Сопроводительная документация\ЛЗК_<шифр>.xlsx`. Сборка может лежать и вне структуры заказа —
в любой папке: тогда книга `ЛЗК_<шифр>.xlsx` ложится прямо рядом со сборкой, новых папок программа не создаёт.

### Как её сделать

1. Открыть главную сборку изделия, нажать **«Ведомость ЛЗК»**. Если изделие меняли после проверки — сначала вопрос
   «Проверить сейчас / Продолжить как есть» (раздел 7, «Версия изделия»).
2. Окно **«Операции»**: строка на каждую деталь и сборку, галочки — лазерная резка листа, лазерная резка трубы,
   гибка, сварка, механическая сборка, покраска. Галочки уже расставлены по модели (листовой металл → лазер
   листа, труба → труборез, сварные швы → сварка, металл → покраска). Конструктор проверяет и поправляет.
3. Над таблицей: **изделий в заказе**, **срок отгрузки**, **цвет**. Можно не заполнять — это потом делается в
   самой книге.
4. «Сформировать». Программа записывает операции и габариты в модели, запускает SWTools (он без окна выгружает
   состав с картинками) и строит книгу. Минута-две. Деталь, в которой у вас несохранённые правки, программа не
   сохраняет — операции в неё записаны, сохраните её сами.

Старая книга не пропадает: в структуре заказа она уходит в `_Аннулировано`, вне её — заменяется, а её копия
остаётся у конструктора на компьютере (путь — в окне «Замечания»). **Всё, что введено в старой книге** (количество,
срок, цвет, нормы, технологические указания), **переносится в новую** — пересобирать книгу можно без страха.
Модель, которую нельзя записать (занята коллегой, только для чтения), книге не мешает — её операции идут в книгу.
Если рядом со сборкой писать нельзя совсем, книга сохраняется в папку «Документы».

### Листы книги

| Лист | Для кого | Что на нём |
|---|---|---|
| **Паспорт** | начальник производства | изделие, заказ, № заявки, **изделий в заказе**, **срок отгрузки**, цвет, отметка «Готово к производству». Жёлтые ячейки — для ввода |
| **Ведомость** | все | весь состав на 1 изделие: картинка детали, обозначение, наименование, материал, габарит, масса, количество, операции; справа — **Категория** (сборка, деталь, покупное, материал), **Участки**, **Всего на заказ**. Таблицу можно сортировать и фильтровать кнопками в шапке — картинки едут вместе со строками |
| **Заготовительный** | труборезы, гибка, лазер | что резать и гнуть: сортамент, длина заготовки, на 1 изделие и всего |
| **Сварочный** | сварщики | сварные узлы и их детали, масса |
| **Покрасочный** | покраска | что красить, площадь, сколько краски и банок; цвет из паспорта |
| **Комплектовочный** | склад, сборка | механические сборки, покупные изделия с кодом 1С |
| **Расход** | склад, снабжение | калькулятор: сколько хлыстов трубы и профиля, метров, кг, сколько листов, сколько краски на весь заказ |
| **Нормы** | технолог | длина хлыста, захват трубореза, торцовка, ширина реза, деловой остаток, размер листа, норма краски — можно поменять под заказ |

На каждом листе участка вверху — количество и срок, внизу — «Технологические указания» (пишет технолог прямо в
книге, при пересборке не теряются) и строки для подписей начальника КТО и начальника участка.

### Главное: книга считает сама

Все числа, которые зависят от количества и норм, — **формулы Excel**. Поменяли в «Паспорте» 41 на 100 — все листы
пересчитались мгновенно. Поменяли на листе «Нормы» захват с 200 на 600 мм — пересчитались хлысты.

**Как считаются хлысты** («пакетом» одинаковых длин из хлыста 6 м):

- сколько заготовок влезает в один хлыст = (6000 − захват − торцовка) ÷ (длина заготовки + рез), с
  округлением вниз;
- сколько хлыстов = всего заготовок ÷ сколько в хлыст, с округлением вверх.

Пример из проверки на реальном изделии: 82 заготовки по 556 мм → по 10 в хлыст → 9 хлыстов.

### Откуда нормы и тексты

- **Нормы** — из справочника `Нормативы_производства.xlsx` (лежит над папками заказов; правит начальник КТО по
  предложению технолога). Нет справочника — берутся стандартные: хлыст 6000, захват 200, торцовка 20, рез 0,5,
  деловой остаток 500, лист 1250×2500, краска 140 г/м² + 15 % потерь, банка 25 кг.
- **Тексты бланков** — названия операций участков, указания по умолчанию, кто подписывает — из справочника
  `ЛЗК_бланки.xlsx`. Его правит владелец без программиста. Образец —
  `02_Шаблоны_и_Форматки\Справочники\ЛЗК_бланки.xlsx`.

### Пометки в книге

- **«?»** — чего-то не хватает: у детали нет материала, массы, операций, у покупного — кода. Изделие с «?» не
  пройдёт «Готово к производству».
- **«*»** у длины — труба нарисована не как элемент сварной конструкции, длина взята по наибольшему габариту.
  Надо проверить.
- Все замечания показывает окно «Замечания» сразу после сборки книги: пометки «?» — жёлтые, «*» — к сведению.

## 9. Что получает цех

### Нестандартное изделие — кнопка «Готово к производству»

Когда изделие готово, конструктор открывает главную сборку и жмёт **«Готово к производству»**. Кнопка:

1. Проверяет: книга ЛЗК есть и нового образца, не открыта в Excel, на компьютере есть Excel.
2. **Заново** проверяет всё изделие (как «Проверить изделие»). Итог должен быть ГОТОВО: в том числе книга ЛЗК и
   выгрузка сделаны по той же версии изделия. Старому отчёту кнопка не верит. Если не ГОТОВО — останавливается и
   ничего не пишет.
3. Excel пересчитывает книгу и печатает в `02_PDF` каждый лист участка, где есть строки, и лист «Расход»:
   `ЛЗК_<шифр>_Заготовительный.pdf`, `ЛЗК_<шифр>_Сварочный.pdf` и т. д. Старые PDF — в `02_PDF\_Аннулировано`.
4. Ставит в «Паспорте» отметку «Готово к производству: дата, кто».
5. Пишет в папку изделия `_Выдано_<дата>_<время>.txt` — что выдано, кем, когда, с контрольными суммами всех
   файлов. С этого момента изделие считается выданным.
6. Показывает окно с путём к папке изделия — путь уже скопирован, его можно сразу вставить в сообщение
   начальнику производства.

### Стандартное изделие — начальник производства сам

Открывает книгу ЛЗК эталона в базе, вводит в «Паспорте» количество и срок, печатает нужные листы. Конструктор
не нужен.

### Где цех всё берёт

```
<папка изделия>\
   02_PDF\                             чертежи + листы участков ЛЗК_<шифр>_<участок>.pdf
   03_ЧПУ\Лазер_Лист\  03_ЧПУ\Труборез\   файлы для станков
   04_Сопроводительная документация\ЛЗК_<шифр>.xlsx   книга с калькулятором
   _Выдано_<дата>.txt                  изделие выдано
```

Правила для цеха:
- Работать только с изделием, у которого есть `_Выдано_…txt`.
- Есть файл с `_Изм1` — работать по нему. Старые файлы лежат в `_Аннулировано` и не используются.
- Цех только читает, ничего не может испортить.
- Замечание к чертежу — технологу, технолог — конструктору. По телефону чертежи не правятся.

## 11. Как ставится и обновляется программа

**У конструктора — один раз и при обновлениях:**

1. Двойной щелчок по
   `\\Synology_TR\Конструкторский отдел\_Библиотека проектирования\_инструменты_конструктора\01_Настройки_SolidWorks\Настройка_Рабочего_Места_SolidWorks.exe`.
2. Первый раз вписать свою фамилию и организацию, нажать «Установить / Обновить».
   При следующих запусках обновление начинается само через 5 секунд.
3. Дождаться «Готово. Запустите SolidWorks.»

Что делает установка: закрывает SolidWorks (предложит сохранить), кладёт макросы и надстройку в локальную папку
компьютера, **сбрасывает настройки SolidWorks к стандарту отдела** (у всех одинаково), настраивает пути к
шаблонам и библиотеке на сервере, ставит кнопки, шрифты ГОСТ, Drew и SWTools. Права администратора Windows
спросит только для Drew и SWTools.

**Лицензию SWTools** каждый активирует сам один раз в окне SWTools — без неё «Ведомость ЛЗК» не работает и
скажет об этом.

**Шаблоны, штампы, библиотека материалов** читаются прямо с сервера — исправили там, у всех обновилось сразу.
Макросы и надстройка — после повторного запуска окна настройки.

**Администратор** выпускает новую версию скриптом `Publish-EskdToolkit.ps1`: он собирает программу, прогоняет
автопроверки и копирует всё на сервер. Номер выпуска и дата — в `toolkit_release.json` на сервере.
Текущий выпуск — **2026.09.19.0855**.

## 12. От каких ошибок система защищает

| Ошибка | Что делает система |
|---|---|
| Забыли заполнить штамп, ошиблись в обозначении | заполняет сама из имени файла при сохранении |
| Материал записан криво | берёт из библиотеки ГОСТ |
| Масса устарела после изменения | пересчитывает при каждом сохранении |
| Отдали в цех недоделанное изделие | «Готово к производству» заново проверяет всё и не выдаёт без ГОТОВО |
| Тихо поменяли выданный чертёж | выгрузка не перезаписывает выданные файлы; проверка изделия замечает правку выданного без ревизии; изменение — только «Новой ревизией» с журналом |
| Цех работает по старой версии | старые файлы уходят в `_Аннулировано`, новые — с `_Изм1`; листы участков перепечатываются |
| Испортили эталон в базе | «Сделать независимым» проверяет, что эталон не изменился; «Снимок эталона» хранит версии |
| Ошиблись в расчёте хлыстов | считают формулы по нормам, а не человек |
| Потеряли введённое при пересборке книги | количество, срок, цвет, нормы, указания переносятся в новую книгу |
| Удалили файл | ничего не удаляется — всё в `_Аннулировано`; плюс снимки сервера каждый час |
| Архив записался наполовину | «Закрыть заказ» сверяет копию, недописанное убирает, рабочую папку не трогает |
| Файл открыт у коллеги | кнопки называют такой файл и останавливаются, ничего не портят |

| Количество и нормы — в окне выдачи, заново каждый раз | Количество и срок — в «Паспорте» книги, нормы — на листе «Нормы»; меняются в любой момент |

ЛЗК» — новая книга появится в нужном месте, старая уйдёт в `_Аннулировано`.

## 14. Чего система пока не умеет и что ещё сделать

**Ограничения:**

- **Только SolidWorks.** Кнопки работают с изделиями, нарисованными в SolidWorks. Изделия в КОМПАС-3D и корпусная
  мебель в bCAD — по-прежнему руками; раскладку файлов по папкам помогает сделать скилл `kto-folders`.
- **Нужен Excel.** Без Excel книга ЛЗК строится, но PDF листов «Готово к производству» не напечатает.
- **Значок начала координат** остаётся на картинках деталей: SolidWorks 2025 при попытке скрыть его в
  невидимой модели падает, поэтому программа его не трогает.
- **Трубы, нарисованные обычным телом** (не элементом сварной конструкции), получают длину по наибольшему
  габариту с пометкой «*». Гнутые трубы — длину заготовки задаёт конструктор (размер `RD1`).
- **Код 1С** покупных берётся из свойства модели; нет свойства — ячейка пустая (это данные снабжения).

**Что осталось сделать людям:**

1. **Сисадмин** — дать группе цеха (`prod_view`) право **только чтения** на `_Заявки` (подробно — «Задание
   сисадмину», изменение от 18.09).
2. **Каждый конструктор** — запустить окно «Настройка рабочего места» из общей папки, чтобы получить новую версию;
   активировать лицензию SWTools, если ещё не активирована.
3. **Владелец** — при желании поправить тексты бланков и подписи в `ЛЗК_бланки.xlsx` и положить его рядом с
   `Нормативы_производства.xlsx`.
4. **Проверка на живом изделии** — сделать книгу ЛЗК и «Готово к производству» на одном реальном заказе,
   показать листы участков цеху.

**Техническое состояние (для администратора):** автопроверки — модульные 107 из 107, статические 33 из 33,
контрактные 9 из 9. Сценарии в SolidWorks: в полном прогоне 117 из 121 прошли; 4 упавших исправлены и при
повторном запуске прошли. Сценарий golden master в полном прогоне прошёл, а при повторных запусках падает:
SolidWorks закрывается на «Сохранить как», причём так же и на прежней версии программы. Значит, это сбой
SolidWorks на этом компьютере — нужно перепроверить после перезагрузки.

## 15. Словарик

| Слово | Что значит |
|---|---|
| **Надстройка** | программа, встроенная в SolidWorks; у нас — вкладка «ЕСКД» |
| **Главная сборка** | файл всего изделия в `01_3D`, например `85T.СМ.00.000 Кровать.sldasm` |
| **Шифр** | обозначение главной сборки без нулей: `85T.СМ`, `ТС-52` |
| **Эталон** | стандартное изделие в базе, из которого берут детали |
| **БЧ** | безчертёжная деталь — описывается одной строкой в спецификации |
| **Исполнение** | вариант детали в одном файле (конфигурация -01, -02) |
| **ЛЗК** | лимитно-заборная карта: что, сколько и из чего делать |
| **Участок** | заготовительный, сварочный, покрасочный, комплектовочный |
| **Хлыст** | труба или профиль целиком, обычно 6 м |
| **Захват** | кусок хлыста, который держит труборез и который не идёт в дело |
| **Торцовка** | срез кривого конца хлыста |
| **КИМ** | коэффициент использования металла: какая доля хлыста ушла в детали |
| **Деловой остаток** | обрезок, который ещё пригодится (от 500 мм) |
| **Ревизия, `_Изм1`** | номер изменения документа после выдачи |
| **`_Аннулировано`** | папка для старых версий; ничего не удаляется |
| **Контрольная сумма (SHA-256)** | «отпечаток» файла: если файл изменился хоть на байт — отпечаток другой |
| **DXF / IGS** | файлы для лазера (развёртка листа) и для трубореза (труба) |
