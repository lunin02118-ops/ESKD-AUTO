# Инструкция И-01. Начальник КТО / Главный конструктор

**Для кого:** Начальник КТО, Главный конструктор; на время отсутствия — назначенный заместитель.
**Основание:** Регламент КТО «Металл» v2.2 — части 3 и 6, §2.6–2.8.
**Дата:** 14 сентября 2026 г.
**Утверждает:** Начальник КТО / Главный конструктор Лунин В. В.

---

## 1. Ваша роль

Вы отвечаете за движение заказа от служебной записки до цеха и за достоверность документации:

1. Классификация позиций служебной записки (СЗ): стандартность и направление.
2. Задачи и исполнители — в Битрикс24; выдача исполнителям доступа к папке заказа.
3. Приёмка КД и публикация комплекта в цех.
4. Решения по изменениям эталонов стандартных изделий и утверждение извещений об изменении.
5. Закрытие заказа и архив.
6. Контроль журналов: изменений заказов, доступов, сбоев сохранения.

## 2. Ваши папки и права

| Папка | Ваши права |
| :--- | :--- |
| `Z:\` — вся общая папка `KTO` | чтение и запись (группа `kto_admins`) |
| `Y:\` — архив `KTO_ARHIV` | чтение и запись; записанное в архив изменить нельзя (WriteOnce) |

## 3. Маршрут заказа

**Шаг 1. Задача и папка заказа.** Задача с исполнителями и сроками — в Битрикс24. Папку заказа создать на своём ПК:

```powershell
powershell -ExecutionPolicy Bypass -File "Z:\00_ИНСТРУМЕНТЫ\Шаблоны_заказа\New-OrderFolder.ps1" -Number 250-АСТ -Object Школа12
```

Положить `СЗ_250-АСТ.pdf` в корень заказа.

**Шаг 2. Разметка.** Заполнить `Разметка_СЗ.xlsx` — для каждой позиции:

| Признак | Значения |
| :--- | :--- |
| Стандартность | `СТД` — эталон без изменений; `ТИПОВОЕ` — эталон с небольшими изменениями; `НЕСТАНДАРТНОЕ` — новое изделие |
| Направление | `МЕТАЛЛ`, `КОРПУС`, `КОМБИ` (металл и корпус) |

Плюс шифр, эталон (для типовых обязательно), исполнение, тираж, RAL, ссылка на задачу Битрикс24. Исполнителей и сроки в разметку не вносить — они в Битрикс24.

**Шаг 3. Папки изделий и доступ.** Для каждой позиции `ТИПОВОЕ` и `НЕСТАНДАРТНОЕ`:

```powershell
powershell -ExecutionPolicy Bypass -File "Z:\00_ИНСТРУМЕНТЫ\Шаблоны_заказа\New-OrderFolder.ps1" -Number 250-АСТ -Object Школа12 -Product "И01_Стол_L1400" -Designation "250-АСТ-Т01.00" -Direction Металл
```

- `-Direction Корпус` — папка в `01_Корпус\`.
- Изделие `КОМБИ` — запустить скрипт для каждого направления, где есть работа. Каждый конструктор делает свою часть в своей папке; кто финализирует общую сборку и техкарту изделия, конструкторы решают сами и отмечают в задаче Битрикс24.

Затем выдать исполнителям из задачи Битрикс24 запись на папку заказа (раздел 5, процедура А).

**Шаг 4. Контроль хода** — в задаче Битрикс24.

**Шаг 5. Приёмка.** Четыре проверки каждого изделия:

| Проверка | Как | Брак, если |
| :--- | :--- | :--- |
| Ссылки | SolidWorks → Файл → Открыть → выделить сборку → «Ссылки…» | есть пути на `C:\`, `D:\`, чужой заказ, `_Черновики` |
| Pack and Go | Проводник → ПКМ по сборке → SOLIDWORKS → Pack and Go | красные значки «файл не найден»; нет чертежей новых деталей |
| Перестроение | открыть сборку, Ctrl+Q | ошибки в дереве; оборванные размеры в чертеже; спецификация не обновлена |
| ЕСКД | вкладка ЕСКД → «Синхронизировать» | окно предупреждений не пустое; нет дроби материала или массы |

Замечания — комментарием в задаче Битрикс24. После исправления — нормоконтроль (технолог).

**Шаг 6. Новые покупные изделия.** Если в `01_3D\Покупные\` есть файлы: «серийное» → заявка куратору баз; «разовое» → остаётся в заказе.

**Шаг 7. Свод и публикация.** Технолог запускает свод заявки и проверяет листы. Вы утверждаете `Заявка_250-АСТ.xlsx` и вместе с технологом копируете комплект в `Z:\04_ПРОИЗВОДСТВО\250-АСТ_Школа12\`. С этого момента документы выданы, и любое их изменение оформляется по разделу 4.

**Шаг 8. Закрытие заказа** после отгрузки:

1. Для каждого изделия `ТИПОВОЕ` и `НЕСТАНДАРТНОЕ` с металлической частью: открыть сборку → Файл → Pack and Go → ☑ «Включить чертежи» → папка `Y:\2026\250-АСТ_Школа12\Комплекты\И01_Стол_L1400\` → ☑ «Сохранить в одну папку» → «Сохранить».
2. Скопировать папку заказа:
   ```powershell
   robocopy "Z:\03_ЗАКАЗЫ\250-АСТ_Школа12" "Y:\2026\250-АСТ_Школа12" /E /COPY:DT /R:2 /W:5 /LOG+:"Z:\00_ИНСТРУМЕНТЫ\_Журнал_ИТ_архив.log"
   ```
3. Снять запись у исполнителей (процедура Б).
4. Переименовать папку в `Z:\03_ЗАКАЗЫ\_Сдано\250-АСТ_Школа12`.

Шаг 1 обязателен: детали эталонов подключены к заказу ссылкой, и без комплекта архив через год покажет уже изменённые эталоны.

## 4. Изменения и дефекты

**Главный вопрос для решения:** можно ли старую деталь поставить в новое изделие, а новую — в изделие, собранное раньше?

- **Да** — оформляется изменение с очередным номером.
- **Нет** — новое обозначение: новое исполнение `-0N` эталона или новый документ. Старый документ не меняется.
- **Изменение нужно только одному заказу** — эталон не трогать, исполнитель делает детали независимыми в заказе.

**Изменение документов заказа после выдачи.** Исполнитель ведёт запись в `Журнал_изменений.xlsx` заказа. Ваша отметка нужна, если изменение затрагивает другое изделие, техкарту, покупные или срок. Контроль закрытия записи: статус «Внедрено», в `04_ПРОИЗВОДСТВО` только последняя ревизия.

**Изменение эталона `02_БАЗА`.** Порядок (роль каждого — в И-03):

1. Предложение приходит на лист «Предложения» книги `Z:\02_БАЗА\_Извещения\Книга_регистрации_ИИ.xlsx`.
2. **Вы решаете не позже следующего рабочего дня:**
   - изменение или новое обозначение;
   - какие открытые заказы затронуты: в `Разметка_СЗ.xlsx` открытых заказов найти строки, где `Шифр` или `Эталон` равен шифру эталона;
   - что делать с каждым затронутым заказом: принять изменение или сохранить прежнюю ревизию (тогда исполнитель заказа до правки эталона делает детали независимыми);
   - номер `ИИ-КТО-2026-NNN` на листе «Извещения»; исполнитель и срок — задачей в Битрикс24.
3. Если исполнитель — не куратор баз, выдать ему временную запись на папку эталона (процедура В).
4. Утвердить подписанное извещение (подписи «Составил» и «Нормоконтроль» уже стоят).
5. После внедрения — снять временную запись (процедура Б), статус «Внедрено» в книге регистрации.

**Срочно — брак в цеху.** Мастер останавливает операцию. Вы определяете, кто и как немедленно исправляет файлы в `04_ПРОИЗВОДСТВО`, оформление следует за исправлением.

## 5. Доступы: процедуры

Выполняются в File Station: `https://nas-kto:5001` → File Station. Каждую выдачу и снятие записать на лист «Доступы» журнала `Z:\00_ИНСТРУМЕНТЫ\_Журнал_ИТ.xlsx`.

**А. Выдать исполнителю запись на заказ:**

1. `KTO` → `03_ЗАКАЗЫ` → выделить папку заказа.
2. ПКМ → «Свойства» → «Разрешение» → «Создать».
3. Пользователь — исполнитель; тип — «Разрешить»; применить к — эта папка, дочерние папки и файлы; разрешения — «Чтение» и «Запись», **без** «Администрирования» → «Готово».
4. «Сохранить»; на вопрос о подпапках — «Да».
5. Проверка — процедура Г.

**Б. Снять запись:** папка → «Свойства» → «Разрешение» → выделить **чёрную** запись пользователя → «Удалить» → «Сохранить». Серые записи групп не трогать.

**В. Временная запись в эталон:** как А, но на папку эталона `02_БАЗА\<раздел>\<шифр>`; срок — срок извещения.

**Г. Проверить права:** папка → «Свойства» → «Разрешение» → «Дополнительные параметры» → «Инспектор разрешений» → пользователь.

**Нельзя:** ставить «Запретить»; давать «Администрирование»; удалять унаследованные записи; выдавать запись группе `kto_metall` на весь `03_ЗАКАЗЫ`.

Новые сотрудники, увольнения, веб-доступ начальника производства — распоряжение сисадмину (И-02).

## 6. Периодический контроль

| Когда | Что |
| :--- | :--- |
| Ежедневно | задачи заказов в Битрикс24; лист «Предложения» книги регистрации ИИ |
| Еженедельно | журналы изменений открытых заказов: нет записей «В работе» старше недели |
| Ежемесячно | лист «Доступы»: явные права только у открытых заказов, временных прав на эталоны нет; лист «Сбои сохранения»: пороги перехода на PDM (регламент §2.7) не превышены |
| Раз в 6 месяцев и при смене версии SolidWorks | пересмотр регламента и инструкций |

## 7. Если что-то пошло не так

| Ситуация | Действие |
| :--- | :--- |
| Конструктор не может сохранить файл заказа: «только чтение» | контекстное меню «Кто открыл»; если никто — процедура Г; нет записи — процедура А |
| Файл повреждён после сохранения | конструктор действует по И-04 раздел 6; при необходимости восстановление из снимка через «Предыдущие версии»; запись сисадмину |
| В цеху изготовили деталь по старой ревизии | остановить; проверить `04_ПРОИЗВОДСТВО` и `_Аннулировано`; указание о заделе; запись в журнал заказа |
| Изменение эталона уже внесено, а заказу нужна прежняя ревизия | исполнитель заказа берёт копию из `<эталон>\_Версии\ИзмN\` и подключает её в заказе вместо эталонной детали |
