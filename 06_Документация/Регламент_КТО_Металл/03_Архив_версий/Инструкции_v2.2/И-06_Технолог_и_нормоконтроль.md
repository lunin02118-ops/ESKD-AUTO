## 3. Нормоконтроль

Проверяется каждый чертёж перед выдачей и каждый изменённый чертёж.

| № | Что проверить |
| :---: | :--- |
| 1 | Обозначение и наименование совпадают с именем файла; на вкладке ЕСКД «Синхронизировать» — без предупреждений |
| 2 | Графа 3 — дробь материала из библиотеки ГОСТ; графа 5 — масса |
| 3 | Покрытие указано в ТТ и в свойстве `Покрытие` |
| 4 | Формат, масштаб, основная надпись заполнены; спецификация SpecEditor соответствует сборке |
| 5 | Размеры, допуски, шероховатость, ТТ — по ЕСКД; нет оборванных размеров |
| 6 | Для изменённого чертежа заполнена таблица изменений: «Изм.», «Лист», «№ докум.» (обозначение ИИ или `Ж-<заказ>-N`), подпись, дата; PDF с суффиксом `_ИзмN` |

Результат: подпись в основной надписи (свойство `Нормоконтроль`, макрос MProp). Замечания — комментарием в задаче Битрикс24.

## 4. Техкарта и свод заявки

**Техкарта на 1 шт** — 5 листов, ключ во всех листах — обозначение.

| Лист | Проверить |
| :--- | :--- |
| `1_Заготовка` | каждая деталь из спецификации; материал однострочной записью; длина `RD1`; количество; имя файла ЧПУ существует |
| `2_Сварка` | узлы и входящие; шов по ГОСТ 5264 или 14771, катет; контрольные диагонали |
| `3_Покраска` | RAL, тип поверхности, площадь, количество |
| `4_Комплектация` | покупные с поставщиком и кодом |
| `5_Списание` | нормы расхода по материалам, коэффициент отхода |

**Свод заявки** (после скрипта Д-47; до него — вручную по той же схеме):

```powershell
python "Z:\00_ИНСТРУМЕНТЫ\_Инструменты_Конструктора\10_Свод_заявки\Свод_заявки.py" "Z:\03_ЗАКАЗЫ\250-АСТ_Школа12"
```

1. Открыть `Заявка_250-АСТ.xlsx`, лист «Проверки»: все пункты зелёные; исправления шифров перенести в разметку; позиции `КОРПУС` «без техкарты» — уточнить у конструктора корпуса.
2. Проверить листы 1–5 и лист «Комплект».
3. Передать Начальнику КТО на утверждение.

## 5. Выдача в производство

1. Скопировать утверждённый комплект в `Z:\04_ПРОИЗВОДСТВО\250-АСТ_Школа12\`: заявка, PDF, DXF, IGS всех изделий `ТИПОВОЕ` и `НЕСТАНДАРТНОЕ` обоих направлений; ссылки на эталонные PDF для позиций `СТД` — на листе «Комплект».
2. Сообщить мастерам участков и ОМТС о новом заказе.

## 6. Изменения

**Изменение документов заказа после выдачи** (И-04, раздел 7):

1. Проверить запись в журнале заказа: указание о заделе понятно мастеру.
2. Нормоконтроль изменённого чертежа.
3. Если изменились нормы или состав — пересвод заявки; новая заявка сохраняется как `Заявка_250-АСТ_Изм1.xlsx`.
4. В `04_ПРОИЗВОДСТВО\<заказ>\`: новые файлы положить, прежние (включая прежнюю заявку) перенести в `_Аннулировано\`.
5. Сообщить мастеру и ОМТС; бумажные копии в цеху заменить, старые изъять.
6. Отметка «внесено в копии» в журнале заказа.

**Изменение эталона по извещению** (И-03, раздел 6):

1. Указание о заделе для извещения: использовать, доработать (как именно) или в брак.
2. Поправить техкарту эталона при изменении норм.
3. Подпись «Нормоконтроль» в извещении.
4. После утверждения — заменить файлы в `04_ПРОИЗВОДСТВО` у затронутых заказов, которые ещё не изготовлены.

## 7. Матрица форматов ЧПУ

1. Для станков КТО — только IGS (труба) и DXF (лист).
2. Для каждого станка в `Матрица_форматов_ЧПУ.xlsx`: станок, программа и версия, утверждённые настройки экспорта IGES (тип тел или поверхностей, единицы мм), кто и когда проверил.
3. Новые настройки — только после пробного импорта трёх деталей: прямой рез, рез под углом, отверстия на двух гранях.
4. Признак неудачного импорта трубы в TubesT — сечение `0.00 x 0.00 x 0.00`. Файл возвращается конструктору.

## 8. Нельзя

- Выдавать в производство документы без нормоконтроля и утверждения Начальника КТО.
- Оставлять в `04_ПРОИЗВОДСТВО` рядом две ревизии одного файла.
- Исправлять модели и чертежи вместо конструктора, кроме срочного исправления в копии для предотвращения брака с последующей записью.
