## 1. Пять принципов

1. **Файлы живут только на `Z:`.** Ни одной модели на рабочем столе, флешке или диске `D:`. Открыл с `Z:`, сохранил на `Z:`.
2. **Одно место для каждого вида данных.** Модели, чертежи, файлы для станков, ведомости, история изменений — в папке изделия на `Z:`. Кто делает и к какому сроку — в задаче Битрикс24. Настройки ПК — в конфигураторе. Ничего не дублируется.
3. **Правило есть, если его выполняет кнопка.** Всё, что можно сделать автоматически, делает вкладка ЕСКД (ТЗ-02). Человек принимает решения: что стандартное, что менять, принять или вернуть. Пока кнопки нет — то же руками, по памятке.
4. **Доверие по умолчанию, ограничение — исключение.** Конструкторы пишут во все заказы. Защита от порчи — блокировки SolidWorks, снимки NAS каждый час, архив без права удаления. Закрыть доступ к отдельному заказу можно, но это решение Начальника КТО, а не ежедневная процедура.
5. **Выдано — значит, зафиксировано.** До выдачи в цех изделие — черновик, правится свободно. После выдачи любое изменение — только через «Новую ревизию» с причиной, номером и записью в журнал. Журнал пишет кнопка, не человек.

## 2. Где что лежит и кто пишет

### 2.1. Диск `Z:` — рабочая папка КТО

```text
Z:\
├── 00_ИНСТРУМЕНТЫ\          инструментарий ЕСКД (установка запуском exe отсюда)
├── 01_БИБЛИОТЕКА\           материалы, покупные, шаблоны, форматки
├── 02_БАЗА\                 стандартные изделия (эталоны)
│   └── СТ-1200\             01_3D  02_PDF  03_ЧПУ  Ведомость_СТ-1200.xlsx  Изменения.xlsx  _Версии\
├── 03_ЗАКАЗЫ\               текущие заказы
│   ├── 52_Школа7\           служебка, сводные заявки, _Выдано_*.txt
│   │   ├── ТС-52-Т1\        01_3D  02_PDF  03_ЧПУ  Ведомость_ТС-52-Т1.xlsx  Изменения.xlsx  _Аннулировано\  _Проверка.txt
│   │   └── ШК-52-Н1\
│   ├── _Сдано\              закрытые заказы после архивирования (только чтение)
│   └── _tmp\                служебная папка кнопки «Закрыть заказ»
└── 04_ПРОИЗВОДСТВО\         выдано в цех
    └── 52_Школа7\           01 КД в PDF  \  02 ЧПУ и Раскрой\Лазер_Лист  \Труборез  \  03 Заявки в цеха  \  _Аннулировано
```

### 2.2. Диск `Y:` — архив

`Y:\<год>\<заказ>\` — сданные заказы: комплект каждого металлического изделия (сборка со всеми деталями и чертежами в одной папке) и копия папки заказа. Папка на NAS с защитой от удаления (WriteOnce). Пишет только кнопка «Закрыть заказ», удалить не может никто.

### 2.3. Кто куда пишет

| Папка | Пишет | Читает |
| :--- | :--- | :--- |
| `00_ИНСТРУМЕНТЫ`, `01_БИБЛИОТЕКА` | куратор баз; публикация инструментария — администратор инструментария | все |
| `02_БАЗА` | только куратор баз | все, производство — через веб (File Station) |
| `03_ЗАКАЗЫ` | все конструкторы, Начальник КТО, технолог | КТО |
| `04_ПРОИЗВОДСТВО` | кнопка «Выдать в производство» (Начальник КТО, технолог) | цех, склад, начальник производства — через веб |
| `Y:` | кнопка «Закрыть заказ» (Начальник КТО) | Начальник КТО |

Права выдаются группами на NAS один раз (задание сисадмину). Личная учётная запись у каждого; пароль свой. Начальник КТО — администратор в рамках папки КТО (делегирование DSM), не администратор NAS.

### 2.4. Защита от потери

- **Снимки NAS** каждый час, хранятся 48 часовых и 30 суточных, видимы пользователям. «Пропал файл» — сисадмин возвращает из снимка за минуту.
- **Резервная копия** папки КТО — по расписанию на отдельный носитель (сисадмин).
- **SolidWorks:** резервные копии и автовосстановление включены профилем конфигуратора; папка резервных копий — локальная, не `Z:`.
- **Блокировки:** SolidWorks ставит `~$`-файл на открытый документ. Второй пользователь открывает только для чтения. Это защита, а не ошибка.

## 3. Что такое изделие: классификация и шифры

Каждая позиция заказа классифицируется по двум признакам. Решает конструктор, глядя в служебку; спорное — Начальник КТО.

| Признак 1 | Что это | Где живёт |
| :--- | :--- | :--- |
| **СТД** стандартное | есть в `02_БАЗА`, делается без изменений | в заказе папки нет; при выдаче берётся из базы |
| **ТИП** типовое | стандартное с небольшими изменениями | папка в заказе; сборка — копия эталона, изменённые детали отвязаны |
| **НОВ** новое | такого не было | папка в заказе |

| Признак 2 | Кто делает |
| :--- | :--- |
| **МЕТАЛЛ** | конструктор по металлу |
| **КОРПУС** | конструктор корпусной мебели |
| **КОМБИ** | оба, каждый в своей папке изделия; кто собирает финальную сборку — договариваются сами и сообщают Начальнику КТО. Зеркальных папок нет |

**Шифры.** Стандартное: `<Тип>-<индекс>` (`СТ-1200`, `СТ-800`). Изделие заказа: `<Тип>-<№ заказа>-<Т|Н><n>` (`ТС-52-Т1` — стол, заказ 52, типовое № 1; `ШК-52-Н1` — шкаф, новое № 1). Деталь: `<шифр изделия>.<узел>.<деталь>` (`ТС-52-Т1.01`, `ТС-52-Т1.02.03`). Имя файла — `<Обозначение> <Наименование>.<расш>`; надстройка сама берёт из имени обозначение и наименование в свойства. Переименовывать файлы в Проводнике нельзя — только «Сохранить как» из SolidWorks.

## 4. Жизнь заказа

### 4.1. Три состояния изделия

| Состояние | Что можно | Как узнать |
| :--- | :--- | :--- |
| **Черновик** | править, пересохранять, перевыгружать файлы сколько угодно | в папке заказа нет `_Выдано_*.txt` с этим изделием |
| **Выдано** (ревизия 0, 1, 2…) | править только через «Новую ревизию» | есть `_Выдано_*.txt`; в сборке свойство `Ревизия` |
| **Сдано** | ничего; читать из `_Сдано` и `Y:` | папка заказа в `03_ЗАКАЗЫ\_Сдано\` |

### 4.2. Порядок по шагам

1. **Служебка.** Отдел продаж присылает служебную записку (Word: описание, количество). Начальник КТО кладёт копию в папку заказа. Кнопки служебку не читают — она для людей.
2. **Папка заказа** `03_ЗАКАЗЫ\<№>_<заказчик>\` — Начальник КТО (скрипт папок или руками).
3. **Задача в Битрикс24** — Начальник КТО: исполнители, срок. Больше ничего: ни история изменений, ни файлы.
4. **Папка изделия** — конструктор: `<шифр>\01_3D, 02_PDF, 03_ЧПУ`. Для ТИП — «Сохранить как» сборки эталона в `01_3D`; стандартные детали остаются в базе, сборка ссылается на них.
5. **Работа.** Что менять — «Сделать независимым с чертежом» (кнопка) в папку изделия; что не менять — не трогать. Свойства пишет надстройка при сохранении; MProp — тот же результат.
6. **Проверка** — кнопка «Проверить изделие», отчёт `_Проверка.txt` в папке изделия. Итог ГОТОВО — к Начальнику КТО. Список критериев — в ТЗ-02, конструктор их не меняет.
7. **Файлы для производства** — кнопка «Экспорт»: один PDF на изделие, DXF развёрток, IGS труб (§7).
8. **Ведомость изделия** — кнопка «Ведомость изделия» (SWTools, пресет «ЛЗК»): на 1 шт — обозначение, наименование, материал, габариты, масса, количество, эскиз, покраска, покупные.
9. **Приёмка** — Начальник КТО смотрит конструкцию по отчёту и чертежам. Оформление уже проверено кнопкой.
10. **Выдача** — кнопка «Выдать в производство»: список «изделие — количество — цвет», проверка всех изделий заново, сводная заявка из ведомостей, копия в `04_ПРОИЗВОДСТВО`, отметка `_Выдано`. Изделия получают ревизию 0.
11. **Изменение после выдачи** — только «Новая ревизия» (§6).
12. **Закрытие** — после отгрузки кнопка «Закрыть заказ»: комплекты в `Y:`, папка в `_Сдано`.

## 5. Правила работы с файлами в SolidWorks

1. **Ссылки только на `Z:`**: этот заказ, `02_БАЗА`, `01_БИБЛИОТЕКА`. Ссылка на рабочий стол — БРАК при проверке.
2. **Порядок поиска ссылок** SolidWorks задан профилем конфигуратора: сначала папка документа, затем `01_БИБЛИОТЕКА`, `02_БАЗА`. Руками в «Параметрах» ничего не менять.
3. **Заимствование из базы** — только «Сделать независимым с чертежом» в папку изделия. Копировать файлы эталона Проводником и переименовывать — нельзя: рвутся ссылки и теряется чертёж.
4. **Стандартные детали в сборке заказа** остаются ссылками на базу. Это правильно. Если стандартная деталь «не подходит» — отвязать её в заказ, а не править в базе.
5. **Бесчертёжные детали** — признак БЧ (кнопка «Деталь БЧ»); у каждой новой детали либо чертёж, либо БЧ.
6. **Материал** — только из корпоративной библиотеки на `Z:`; надстройка пишет марку и сортамент в свойства. Деталь без материала — БРАК.
7. **Сохранение по сети**: перед сохранением большой сборки — «Сохранить» деталей по отдельности; не выключать ПК, пока SolidWorks пишет на `Z:`. Файл «повредился при сохранении» — сисадмину, снимок часовой давности вернёт.
8. **Чужой файл открыт только для чтения** — не «Сохранить как» под другим именем, а спросить коллегу. Проверка покажет, кто держит файл.
9. **Синхронизаторы** (Synology Drive, OneDrive, Dropbox) на папке КТО запрещены: SolidWorks с ними не работает. Прямой сетевой диск.
10. **Резервные копии SolidWorks** — в локальную папку, не на `Z:`; настраивает конфигуратор.

## 6. Изменения и стандартные изделия

Основа — ГОСТ 2.503-2013 (правила внесения изменений), применяется как стандарт организации без бумажных извещений: извещение заменяет строка в `Изменения.xlsx`, которую пишет кнопка.

### 6.1. Что считается изменением

Изменение — правка выданного изделия (§4.1). Правки черновика изменениями не являются и нигде не учитываются.

### 6.2. Новая ревизия изделия заказа

Кнопка «Новая ревизия» (конструктор):

1. спрашивает причину (текст) и код по таблице Б.1 ГОСТ 2.503 (список в кнопке), а также что делать с заделом: **использовать / доработать / в брак**;
2. ставит `Ревизия = N+1`; заполняет таблицу изменений в основной надписи чертежа: «Изм.» — номер, «Лист» — прочерк для однолистового, «№ докум.» — номер строки журнала, подпись, дата;
3. дописывает строку в `Изменения.xlsx` в папке изделия: №, ревизия, дата, кто, документ, что изменено, причина, код, задел;
4. заново выгружает файлы и ведомость с суффиксом `_ИзмN`; прежние — в `_Аннулировано`.

Дальше Начальник КТО повторяет «Выдать в производство»: сводная заявка получает новую ревизию, в цех уходят новые файлы, прежние — в `_Аннулировано` папки производства. Мастер работает по последней ревизии (§7.3).

### 6.3. Стандартные изделия (эталоны)

- В `02_БАЗА` пишет **только куратор баз**. Все остальные — читают.
- У каждого эталона обязательны: главная сборка, чертежи, файлы выдачи, **ведомость** (без неё «Выдать» не возьмёт изделие в сводную), `Изменения.xlsx`.
- **Новый эталон**: конструктор сделал изделие в заказе → решение Начальника КТО «сделать стандартным» → куратор копирует в базу под шифром базы, проверяет, делает ведомость.
- **Изменение эталона**: кнопка «Снимок эталона» (прежняя ревизия — в `_Версии\ИзмN`, строка в журнал с причиной, список открытых заказов, где эталон выдан — применяемость) → правка → «Проверить», «Экспорт», «Ведомость» → «Новая ревизия».
- **Применяемость.** Заказы, где эталон уже выдан, продолжают работать по прежней ревизии — их комплекты в `04_ПРОИЗВОДСТВО` и в архиве не меняются. Решение «доделать по старой или переделать» принимает Начальник КТО по каждому заказу из списка применяемости.
- **Дефект стандартного изделия**, найденный в заказе, — не правится в заказе. Сообщение куратору, изменение эталона по порядку выше; в заказе — при необходимости отвязка детали в заказ как временное решение с записью в журнал изделия.

### 6.4. Чего не ведём

Журналов в Excel, которые заполняет человек; книг регистрации извещений; листов доступов; истории изменений в Битрикс24. Всё это либо пишет кнопка в папке изделия, либо не нужно.

## 7. Выдача в производство

### 7.1. Сводная заявка

Форма — как образец «Производственная заявка 85_Т» (`06_Примеры_документов`): шапка с составом заказа и пять листов:

| Лист | Кому | Что |
| :---: | :--- | :--- |
| 1 | цех металлоизделий | заготовки на тираж: обозначение, сортамент, длина, на 1, всего, операция |
| 2 | сварочный цех | узлы, масса |
| 3 | покраска | узлы под покраску, количество, **цвет — из окна выдачи** |
| 4 | склад ТМЦ | покупные с кодом 1С, на 1, всего |
| 5 | склад / ОМТС | расход и списание по сортаменту: чистый расход, хлысты, кг, КИМ, деловые обрезки, отход |

Цифры считает кнопка из ведомостей изделий × количество; модели при этом не открываются. Нормативы раскроя (хлыст 6000, захват станка 200, керф 4, торцовка, деловой обрезок ≥ 500, лист 1250×2500, норма краски 140 г/м² + 15 %) — в «Настройках ЕСКД», меняет Начальник КТО по предложению технолога.

Блок «Технологические указания» под каждым листом — пустой, его пишет технолог или Начальник КТО. Подписи — внизу листов.

### 7.2. Файлы для станков

| Файл | Кому | Имя | Правило |
| :--- | :--- | :--- | :--- |
| PDF | цех, нормоконтроль | `<Обозначение> <Наименование>[_ИзмN].pdf` | один файл на изделие, все чертежи |
| DXF развёртки | лазер | `<Обозначение> <Наименование>_<толщина>мм_<ширина>х<длина>[_ИзмN].dxf` | только контур развёртки, без линий сгиба и эскизов |
| IGS | труборез | `<Обозначение> <Наименование>[_ИзмN].igs` | IGES, мм, поверхности + кривые; ось трубы — по СК `Труба` в модели, если есть |

IGS — единственный формат для труборезов предприятия (не все читают SAT/STEP). Параметры экспорта зашиты в кнопку; менять руками не нужно.

### 7.3. В цеху

- Файлы берутся только из `04_ПРОИЗВОДСТВО\<заказ>\`, из `03_ЗАКАЗЫ` — никогда (там черновики).
- Есть файл с `_Изм1` — работать по нему; файл без суффикса лежит в `_Аннулировано` и не используется.
- Замечания к чертежу — технологу; технолог — конструктору в задаче; конструктор — «Новая ревизия». По телефону и в мессенджерах чертежи не правятся.

## 8. Рабочее место и ИТ

- **Установка инструментария** — запуск `Z:\00_ИНСТРУМЕНТЫ\...\Настройка_Рабочего_Места_SolidWorks.exe` из сетевой папки, выбор фамилии, «Установить». На ПК создаются локальный экземпляр и ветка реестра; данные читаются с `Z:`. Подробно — руководство, часть II.
- **Параметры SolidWorks** (совместная работа, ссылки только для чтения, папки резервных копий, порядок поиска) — профилем конфигуратора, руками не настраиваются.
- **NAS** — по «Заданию системному администратору»: группы, права по §2.3, делегирование Начальнику КТО, снимки, флажки DSM. После выполнения — 10 ответов сисадмина в таблице задания.
- **Веб-доступ производства** — File Station только на чтение `02_БАЗА` и `04_ПРОИЗВОДСТВО`, без SMB.
- **Плановая проверка** (сисадмин, раз в месяц, 15 минут): снимки есть, резервная копия ушла, место есть, нет забытых `~$` старше суток на `Z:`.

## 9. Роли и кнопки

Подробно — памятки по ролям. Коротко:

| Кнопка вкладки ЕСКД | Кто | Когда |
| :--- | :--- | :--- |
| Синхронизировать | конструктор | реквизиты, материал, масса (обычно сама при сохранении) |
| Деталь БЧ | конструктор | деталь без чертежа |
| Сделать независимым с чертежом | конструктор | стандартную деталь надо изменить под заказ |
| Экспорт для производства | конструктор | PDF, DXF, IGS |
| Проверить изделие | конструктор; Начальник КТО | перед сдачей и при приёмке |
| Ведомость изделия | конструктор; куратор | после проверки, на 1 шт |
| Выдать в производство | Начальник КТО, технолог | заказ готов |
| Новая ревизия | конструктор; куратор | изделие выдано, надо поменять |
| Снимок эталона | куратор | перед изменением стандартного |
| Закрыть заказ | Начальник КТО | заказ отгружен |

Пока кнопки нет — тот же порядок руками, как описано в памятке роли. Регламент от этого не меняется.

## 10. Переходный период

| Что | Сейчас | Когда появится кнопка |
| :--- | :--- | :--- |
| Отвязка детали | «Сделать независимым» + «Сохранить как» чертежа + «Заменить модель» + «Синхронизировать» | одна кнопка |
| Проверка изделия | «Синхронизировать» и осмотр по списку §5 | отчёт `_Проверка.txt` |
| Экспорт | сохранение PDF/DXF/IGS руками с именами по §7.2 | одна кнопка |
| Ведомость | экспорт спецификации SWTools по пресету «ЛЗК» | кнопка запускает и дописывает покраску и покупные |
| Сводная заявка | из ведомостей в Excel руками по форме 85_Т | одна кнопка |
| Новая ревизия | правка штампа заметками, строка в `Изменения.xlsx` руками, файлы `_ИзмN` руками | одна кнопка |
| Снимок эталона | копия папок в `_Версии\ИзмN` руками, строка в журнал | одна кнопка |
| Закрытие заказа | Pack and Go и копирование в `Y:` руками | одна кнопка |

Порядок и имена файлов в переходный период те же, что и после автоматизации, поэтому ничего переделывать потом не придётся.
