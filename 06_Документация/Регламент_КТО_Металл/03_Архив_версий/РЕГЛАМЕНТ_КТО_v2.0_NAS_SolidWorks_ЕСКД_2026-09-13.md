## ЧАСТЬ 1. АРХИТЕКТУРА ДАННЫХ

### 1.1. Принципы

1. **Одна копия данных.** Все модели, чертежи, эталоны и заказы живут только на NAS. Локальные копии CAD-данных не создаются, кроме личных черновиков (`D:\Work\_Черновики\`), которые не выдаются никому.
2. **Прямая работа по SMB.** SolidWorks открывает файлы с `Z:` напрямую. Так работает штатная блокировка: второй пользователь получает файл только для чтения и видит, кто его открыл.
3. **Инструментарий ЕСКД — часть рабочего места.** Надстройка ЕСКД v6, макросы SWplus, шаблоны, форматки, библиотека материалов и профилей устанавливаются на каждый ПК из эталонной копии репозитория `_Инструменты_Конструктора` одним батником. Реквизиты основной надписи, материал (дробь по ГОСТ), масса и обозначения заполняются надстройкой автоматически при сохранении.
4. **Эталон не трогают.** Библиотека и база стандартов доступны конструкторам только для чтения; изменения в них вносит куратор баз по заявке.
5. **Повторное использование через исполнения.** Типоразмеры серийных изделий — конфигурации-исполнения в эталоне (ГОСТ 2.113), а не копии на каждый заказ.
6. **Ничего не удаляется без следа.** Снимки Btrfs, корзина общей папки, архив WriteOnce.

### 1.2. Каноническое дерево (единственное в документе)

Сетевые диски на каждом ПК подключаются по DNS-имени, не по IP: `Z:` = `\\nas-kto\KTO`, `Y:` = `\\nas-kto\KTO_ARHIV`.

## ЧАСТЬ 2. ИНСТРУКЦИЯ СИСТЕМНОГО АДМИНИСТРАТОРА

### 2.1. Synology NAS (DSM 7.2 и новее)

| № | Раздел DSM | Действие | Значение |
| :---: | :--- | :--- | :--- |
| 1 | Панель управления → Пользователь и группа | Создать группы | `kto_admins` (Начальник КТО, сисадмин), `kto_kurator` (куратор баз), `kto_metall`, `kto_korpus`, `kto_tech` (технолог, нормоконтроль), `production` (мастера, ЧПУ, ОМТС) |
| 2 | Там же | Учётные записи | Логин DSM = логин Windows на ПК сотрудника (иначе в `~$`-файлах и ACL будут разные имена). Пароль ≥ 12 символов, политика сложности включена |
| 3 | Панель управления → Общая папка | Создать `KTO` | Том Btrfs; «Включить корзину» (доступ только администраторам); «Включить контрольную сумму данных»; шифрование не требуется |
| 4 | Там же | Создать `KTO_ARHIV` | Том Btrfs; **WriteOnce** (режим Enterprise, блокировка сразу после записи, срок хранения 5 лет) |
| 5 | Общая папка → Права / Windows ACL | Назначить права по дереву §1.2 | Права только группам, никогда — отдельным пользователям. Наследование не разрывать внутри `03_ЗАКАЗЫ` |
| 6 | Файловые службы → SMB → Дополнительно | Протокол | Мин. SMB2, макс. SMB3; «Opportunistic locking» включён; «Durable handles» — выключить, если после аварийного закрытия SolidWorks файлы остаются «только для чтения» (проверить на пилоте); SMB Multichannel — включить при двух и более сетевых портах |
| 7 | Файловые службы → SMB | Прочее | «Локальный главный обозреватель» выключен; журнал передачи выключен (нагрузка) |
| 8 | Внешний доступ | QuickConnect | **Отключить полностью**; DDNS не настраивать; проброс портов отсутствует |
| 9 | Безопасность → Брандмауэр | Правила | Разрешить только подсеть офиса; всё остальное запретить |
| 10 | Безопасность → Учётная запись | Защита | Автоблокировка после 5 неудачных попыток; 2FA для всех членов `administrators`; учётная запись `admin` отключена |
| 11 | Snapshot Replication → Снимки | Папка `KTO` | Каждый час, хранить 48 часовых, 30 суточных, 12 недельных; **неизменяемые снимки** — 7 дней; «Сделать снимки видимыми» — включить (пользователи восстанавливают файлы сами через Проводник → «Предыдущие версии») |
| 12 | Hyper Backup | Задача 1 | Ежедневно 22:00 → внешний USB-диск, ротация Smart Recycle, проверка целостности ежемесячно |
| 13 | Hyper Backup | Задача 2 | Еженедельно → второй NAS/облако вне здания (правило 3-2-1) |
| 14 | Панель управления → Оборудование → ИБП | ИБП | Подключён по USB, безопасное выключение через 5 мин на батарее |
| 15 | Хранилище | SSD-кэш | Кэш чтения на NVMe при наличии слотов; RAID 5/6 или SHR-2, «горячий» резерв при 6+ дисках |
| 16 | Synology Drive | Роль | **Не используется для CAD-папок.** Допускается Team Folder `04_ПРОИЗВОДСТВО` в режиме «только загрузка» для планшетов мастеров |
| 17 | Синология → Сеть | Адресация | Статический IP + DNS-запись `nas-kto` на роутере/сервере; в скриптах и ярлыках — только имя |

### 2.2. Рабочая станция: базовые требования

| Параметр | Требование |
| :--- | :--- |
| SolidWorks | Одна версия и один SP на всех 13 местах (сегодня — SOLIDWORKS 2025 SP по приказу). Обновление SP — в один день, после прогона автотестов инструментария. Пользователям запрещено обновлять самостоятельно |
| Диск | `D:\Work\` на NVMe SSD; сеть 1 GbE минимум, 2.5 GbE — желательно |

| Антивирус | Исключения: процессы `SLDWORKS.exe`, `sldProcMon.exe`, `sldworks_fs.exe`, `swScheduler.exe`; папки `Z:\`, `D:\Work\`, `C:\SW_Backup\`, `C:\SW_AutoRecover\`; расширения `sldprt, sldasm, slddrw, sldlfp, sldmat, swp, swb, slddrt, prtdot, asmdot, drwdot` |

### 2.3. Установка инструментария ЕСКД (обязательно на каждом ПК)

1. Зеркалировать эталон на локальный диск (запуск от имени пользователя; выполняется при первой установке и при каждом обновлении):
   ```powershell
   robocopy "Z:\00_ИНСТРУМЕНТЫ\_Инструменты_Конструктора" "D:\Work\_Инструменты_Конструктора" /MIR /XD .git build_temp runs /R:2 /W:5
   ```
2. Убедиться, что на ПК **нет** папки `D:\Work\_Библиотека проектирования\_Toolbox` (иначе скрипт установки привяжет локальный Toolbox вместо общего, см. `01_Настройки_SolidWorks/Setup_Workstation_SolidWorks.ps1:654-656`).
3. Запустить `D:\Work\_Инструменты_Конструктора\УСТАНОВИТЬ_ЕСКД.bat` (двойной щелчок; батник запросит права администратора, закроет SolidWorks и выполнит 6 шагов: профиль реестра, `Master.ini`, регистрация надстройки, кнопки SWplus, избранные материалы, шрифты ГОСТ).
   Ручной запуск с фамилией и организацией:
   ```powershell
   powershell -ExecutionPolicy Bypass -File "D:\Work\_Инструменты_Конструктора\01_Настройки_SolidWorks\Setup_Workstation_SolidWorks.ps1" -Author "Иванов И.И." -Firm "ТОО «Троя»"
   ```
4. Скрипт сам прописывает пути поиска SolidWorks: основные надписи SWplus, шаблоны документов, базу материалов `Библиотека_Материалов_ГОСТ.sldmat`, профили сварных деталей `Сортамент ГОСТ`, макросы SWplus. Эти пути указывают на **локальную** копию `D:\Work\_Инструменты_Конструктора\` — это правильно: DLL надстройки и макросы должны быть локальными, а библиотека материалов версионируется вместе с ними.
5. Проверка: запустить SolidWorks → вкладка «ЕСКД» есть в детали, сборке и чертеже; в верхней панели 9 кнопок SWplus; в журнале `%TEMP%\eskd_material_sync.log` есть строка `=== ConnectToSW v6.0.0`.
6. Настройки, которые скрипт не задаёт, выставить вручную по §2.4.

2. **Pack and Go (20 с).** Проводник → ПКМ по сборке → SOLIDWORKS → Pack and Go. Нет красных значков «файл не найден», флажок «Включить чертежи» показывает чертежи всех новых деталей.

### 4.1. Рабочее место и дисциплина

- При падении SolidWorks: восстановиться из `C:\SW_AutoRecover\`; удалить свой остаточный `~$`-файл рядом с документом только если файл больше никем не открыт.

### 4.2. Имена файлов и обозначения (регламент инструментария ЕСКД, ч. I, §4)

| Тип | Шаблон имени | Пример |
| :--- | :--- | :--- |
| Деталь | `Обозначение Наименование.sldprt` | `250-АСТ-Т01.10.01 Столешница.sldprt` |
| Сборка | `Обозначение СБ Наименование.sldasm` | `250-АСТ-Т01.00 СБ Стол ученический L1400.sldasm` |
| Чертёж | как у модели | `250-АСТ-Т01.10.01 Столешница.slddrw` |
| Эталон базы | `СТД-<серия><номер>.<узел>.<деталь>` | `СТД-СЛ120.10.01 Столешница.sldprt` |

Разделитель — первый пробел; подчёркивания в имени файла не применяются (надстройка делит имя по пробелу). Обозначение всегда содержит цифры. Схема обозначения заказа: `<№ заказа>-<Тип><№ изделия>.<узел>.<деталь>`; узел `00` — изделие в целом.

**Исполнения** (ГОСТ 2.113): конфигурации `00` (базовое), `01`, `02` … Надстройка сама пишет `Обозначение-01`, `-02` в конфигурации. Столы L1200/L1400/L1600 в эталоне — одно изделие `СТД-СЛ120.00` с исполнениями `00/-01/-02`; заказ на L1400 — позиция `[СТД]` с исполнением `-01`, проектировать ничего не нужно.

После переименования файла в Проводнике, «Сделать независимым» или Pack and Go надстройка считает старое обозначение ручным (Руководство, ч. I, §4.3): очистить `Обозначение` и `Наименование` в MProp и сохранить — реквизиты возьмутся из нового имени.

### 4.3. Материал и покрытие

1. Материал назначается **только** из `Библиотека_Материалов_ГОСТ` (дерево → «Материал» → «Редактировать материал» → категория → типоразмер → «Применить»), либо из девяти избранных. Ручной ввод текста в графу 3 запрещён; надстройка при сохранении заменит его записью библиотеки (единственный источник графы 3), а расхождение покажет в строке состояния.
2. Что попадает в файл при сохранении: `Материал_ФБ` (графа 3 — форма и дробь «сортамент / марка»), `Материал_Таблица`, `Материал_Строка` (одна строка для ведомости), `Масса_ФБ` (графа 5), `Масса_Таблица` — по каждой конфигурации.
3. Нужного типоразмера нет в библиотеке → заявка куратору баз: строка в `Ограничительный_перечень_ТРОЯ.csv` (столбцы: категория, имя в дереве, числитель-сортамент, знаменатель-марка, типоразмер, ГОСТ сортамента, марка, ГОСТ материала, штриховка) → куратор генерирует библиотеку `generate_materials.py` → автотест T0 → публикация в эталон → обновление на ПК по §2.3. Самовольно править `.sldmat` запрещено.
4. **Покрытие** — не материал. Порошковая краска указывается в свойстве детали/сборки `Покрытие` (MProp) в виде `Порошковое, RAL 7035, шагрень, ГОСТ 9.306-85` и в технических требованиях чертежа (макрос TT). Из свойства `Покрытие` и площади поверхности скрипт свода формирует лист «Покраска».
5. Профили сварных деталей — только из `Сортамент ГОСТ` (папка подключена скриптом установки). Профили с личных дисков запрещены.

### 4.4. Подетальная сборка: два допустимых способа

**Способ 1 — классическая сборка «сверху вниз».** В сборке изделия создаётся компоновочный эскиз (skeleton) с габаритами; детали строятся в контексте или по эскизу; каждая труба, стойка, косынка — отдельный `.sldprt` по §4.2.

**Способ 2 — сварная деталь + Save Bodies.** Каркас моделируется одной сварной деталью-мастером `250-АСТ-Т01.10 Рама (мастер).sldprt` в подпапке `01_3D\_Мастер\` (в спецификацию не входит). Затем: ПКМ по папке «Список вырезов» → «Сохранить тела» (Save Bodies): ☑ «Создавать производные детали из подобных тел» (одинаковые трубы — один файл), ☑ «Копировать свойства списка вырезов», ☑ «Создать сборку» → `250-АСТ-Т01.10 СБ Рама.sldasm`; имена файлов тел задать сразу по §4.2. После сохранения открыть каждую производную деталь, убедиться, что материал — из библиотеки (иначе назначить), сохранить. Изменение длины в мастере обновляет все производные детали.

В обоих способах в цех уходит сборка с отдельными деталями. Многотельная деталь без Save Bodies допускается только для концептов в `_Черновики`.

**Длина заготовки.** В каждой детали из проката добавить эскиз `Примечания` со справочным размером `RD1` — длиной заготовки: надстройка использует его для записи БЧ и его же читает скрипт свода (лист «Заготовка»).

### 4.5. Безчертёжные детали (БЧ)

Прямой отрезок трубы, полоса, пластина без отверстий — оформляются без чертежа: назначить материал, сохранить по регламенту имён, нажать «Деталь БЧ» на вкладке ЕСКД. Надстройка запишет `Формат` = БЧ, массу в «Примечание», наименование в три строки (наименование / дробь материала / `L = … мм`). Для БЧ-деталей выпускаются только файлы ЧПУ (§4.9) — чертёж не нужен, это снимает до половины чертежей с типового стола.

### 4.6. Стандартные и покупные изделия

- Крепёж — из Toolbox (стандарт ГОСТ) или из `Z:\01_БИБЛИОТЕКА\01_Крепеж` перетаскиванием; автосопряжения (Mate References) в библиотечных деталях настроены куратором.
- Покупные изделия из библиотеки уже оформлены макросом **SProp** (`Раздел`, поставщик, код); надстройка ЕСКД их не трогает.

### 4.7. Пополнение библиотеки (куратор баз)

### 4.8. Модификация эталона: пошаговое заимствование

**Принцип.** Заранее неизвестно, какие детали затронет доработка: изменение столешницы тянет траверсу, траверса — косынку. Поэтому копируется **только сборка**, а детали отвязываются по одной в тот момент, когда их действительно нужно менять. Перечень выпускаемых деталей получается в конце работы, а не угадывается в начале.

**Страховка.** `Z:\02_БАЗА` доступна только для чтения. Изменить и сохранить эталонную деталь невозможно: при попытке SolidWorks сообщит, что файл только для чтения. Это и есть сигнал «эту деталь нужно отвязать».

**Шаг 1. Копия сборки (1 мин).**

1. Окно → Закрыть все. Открыть `Z:\02_БАЗА\01_Столы\СТД-СЛ120.00\01_3D\СТД-СЛ120.00 СБ Стол ученический.sldasm` (откроется только для чтения).
2. Файл → **Сохранить как** (не «как копию») → папка `Z:\03_ЗАКАЗЫ\250-АСТ_Школа12\02_Металл\И01_Стол_L1400\01_3D\` → имя `250-АСТ-Т01.00 СБ Стол ученический L1400.sldasm`. В разделе «Дополнительно» флажок «Включить все ссылочные компоненты» — **снят**.
3. MProp → очистить «Обозначение» и «Наименование» → Ctrl+S (надстройка заполнит реквизиты по новому имени, §4.2).
4. Проверка: Файл → Открыть → «Ссылки…» — все детали указывают на `Z:\02_БАЗА\…`. Ни одна деталь не скопирована.

**Шаг 2. Отвязка детали — каждый раз, когда её нужно изменить.**

1. В дереве сборки ПКМ по детали → **«Сделать независимым»** (Make Independent). Меняются все экземпляры детали — выделить все экземпляры (Ctrl+клик) до команды. Меняется только часть экземпляров — выделить только их, остальные останутся эталонными.
2. В окне сохранения **сменить папку**: SolidWorks предлагает папку исходного файла, то есть `02_БАЗА`, куда записи нет. Указать `…\И01_Стол_L1400\01_3D\` и имя по §4.2: `250-АСТ-Т01.10.01 Столешница.sldprt`.
3. Открыть новую деталь → MProp → очистить «Обозначение» и «Наименование» → Ctrl+S.
4. Только теперь менять размеры. Ctrl+Q, Ctrl+S — деталь, затем сборка.
5. Изменение потянуло соседнюю деталь — повторить шаг 2 для неё. Сколько нужно раз, столько и повторять.

**Деталь внутри эталонного узла.** Сначала отвязать узел (шаг 2 для подсборки), затем деталь внутри него. Файл эталонного узла только для чтения, и замену детали в нём сохранить нельзя. Порядок всегда сверху вниз: изделие → узел → деталь.

**Правка сделана до отвязки.** Если SolidWorks при сохранении сообщил, что эталонная деталь только для чтения, выполнить для неё шаг 2 и открыть новую деталь. Правка на месте — продолжать. Правки нет — повторить её в новой детали. Эталон при этом не пострадал.

**Отвязали лишнее.** Деталь отвязана, но в итоге не изменилась: ПКМ → «Заменить компоненты» → выбрать эталонный файл из `02_БАЗА` → ☑ «Все экземпляры» → сохранить сборку → удалить неиспользуемую копию из `01_3D\`, предварительно проверив «Ссылками…», что на неё никто не ссылается.

**Шаг 3. Чертежи отвязанных деталей и сборки.** «Сделать независимым» чертёж не копирует, поэтому чертёж переносится с эталона:

1. Открыть чертёж эталонной детали `Z:\02_БАЗА\…\01_3D\СТД-СЛ120.10.01 Столешница.slddrw`.
2. Файл → **Сохранить как** → `…\И01_Стол_L1400\01_3D\250-АСТ-Т01.10.01 Столешница.slddrw`. С этого момента открыт новый чертёж, эталон не тронут.
3. ПКМ по любому виду → **«Заменить модель»** (Инструменты → Заменить модель) → ☑ все виды → выбрать новую деталь `250-АСТ-Т01.10.01 Столешница.sldprt` → ОК.
4. Проверить оборванные (оливковые) размеры и примечания, поправить, обновить ТТ, Ctrl+S.
5. Так же для сборочного чертежа: эталонный СБ-чертёж → «Сохранить как» → «Заменить модель» на новую сборку → обновить спецификацию SpecEditor и позиции.

**Шаг 4. Перечень к выпуску — в конце работы.** Файл → Открыть → сборка → «Ссылки…». Всё, что лежит в папке изделия, — новое: на него выпускается чертёж или оформляется БЧ (§4.5), делаются файлы ЧПУ (§4.9) и строки техкарты. Всё, что лежит в `02_БАЗА`, берётся из эталона: в техкарте ссылка на эталонные PDF.

**Когда уместен Pack and Go.** Только если состав изменений известен заранее целиком: повтор изделия из прошлого заказа (Pack and Go всего изделия с новым префиксом) или передача изделия подрядчику.

**Автоматизация.** Ручной шаг 3 закрывает задача Д-53 — команда «Сделать независимым с чертежом» на вкладке ЕСКД. Она копирует чертёж рядом с новой моделью, перепривязывает его и очищает реквизиты для заполнения по имени.

### 4.9. Выдача в производство: форматы, имена, ревизии

| Формат | Папка | Как получить | Имя файла | Потребитель |
| :--- | :--- | :--- | :--- | :--- |
| PDF | `02_PDF\` | макрос **SaveAsPDF** (кнопка 9 SWplus) из чертежа | `<Обозначение> <Наименование>_Изм0.pdf` | сборка, сварка, ОТК |
| DXF (лист) | `03_ЧПУ\` | ПКМ по плоской грани развёртки → «Экспорт в DXF/DWG»: выход «Развёртка», ☐ линии сгиба, ☐ эскизы, ☑ геометрия; версия R2000, мм, 1:1; сплайны → полилинии, если требует CypNest | `<Обозначение>_S<толщина>_<марка>_x<шт на изделие>.dxf` → `250-АСТ-Т01.10.01_S3_Ст3сп_x1.dxf` | лазер CypCut/CypNest |
| IGS (труба), по умолчанию | `03_ЧПУ\` | Файл → Сохранить как → IGES (*.igs) → «Параметры»: твёрдые тела и поверхности; «Вывод системы координат» — система координат вдоль оси трубы | `<Обозначение>_<профиль>_L<длина>_x<шт>.igs` → `250-АСТ-Т01.20.01_Тр40х40х2_L1350_x2.igs` | труборез, если в матрице не указано иное |
| SAT / STEP (труба) | `03_ЧПУ\` | Файл → Сохранить как → ACIS (*.sat) или STEP AP214; система координат — как для IGS | как для IGS, расширение `.sat` / `.step` | только станки, для которых формат подтверждён в матрице |

**Формат для трубореза задаёт программа конкретного станка, а не регламент.** Поддержка различается по производителю и по версии ПО:

| ПО трубореза | IGS | SAT | STEP | Прочее | Источник |
| :--- | :---: | :---: | :---: | :--- | :--- |
| Friendess TubesT (к TubePro, CypTube) | все версии; ось трубы строго вдоль X/Y/Z | с V1.13 | с V1.47 | IFC, NC1 (Tekla) | документация Bochu |
| Lantek Flex3d Tubes | да | да | да | модели SOLIDWORKS | сайт Lantek |
| BLM ArTube | да | не заявлен | да | XT (Parasolid), IFC | сайт BLM |

Правила:

1. Технолог ведёт `Z:\00_ИНСТРУМЕНТЫ\Матрица_форматов_ЧПУ.xlsx`: станок, ПО и **его версия**, подтверждённые форматы, настройки экспорта, ограничения, кто и когда проверил пробным импортом.
2. Новый формат вводится только после пробного импорта трёх деталей: прямой рез, рез под углом, отверстия на двух гранях. Результат записывается в матрицу.
3. Пока строки для станка нет, выдаётся **IGS** — единственный формат, который читают все перечисленные программы.
4. Для IGS в TubesT ось трубы обязана идти вдоль оси координат. Деталь из Save Bodies (§4.4) сохраняет наклон, заданный в сварной детали. Поэтому для наклонной трубы создаётся система координат вдоль её оси и выбирается при экспорте.
5. Признак неудачного импорта в TubesT — сечение `0.00 x 0.00 x 0.00`. Такой файл возвращается конструктору.

Ревизии: первая выдача `_Изм0`; изменение после выдачи — новая ревизия `_Изм1`, прежний файл переносится в `_Аннулировано\`, запись в `Журнал_изменений.xlsx` (что, почему, кто, дата, затронутые файлы), извещение по ГОСТ 2.503 при изменении уже изготавливаемых деталей. Модели не переименовываются.

### 5.3. Скрипт свода `Свод_заявки.py` (детерминированный, без ИИ)

- **Вход:** `Разметка_СЗ.xlsx` заказа; техкарты по `Шифр`+`Исполнение`: для `СТД` — из `Z:\02_БАЗА\**\Техкарта_<Шифр>_на_1шт.xlsx`, для `МОДИФИКАЦИЯ` — из папок изделий заказа.
- **Логика:** умножить каждую строку на `Тираж`; сгруппировать лист 1 по `Материал_Строка` и толщине/профилю; лист 3 — по RAL; лист 5 — суммы по `Материал_Строка`; добавить лист `Комплект` — перечень PDF/DXF/IGS/SAT с путями (для СТД — из `02_БАЗА`).
- **Выход:** `Заявка_<№>.xlsx` в корне заказа с теми же 5 листами + `Комплект` + `Проверки`.
- **Проверки (останов при ошибке):** у всех позиций заполнены `Тип`, `Шифр`, `Тираж`, `RAL`; техкарта найдена для каждой позиции; в техкарте нет пустых `Материал_Строка`; обозначения из техкарты существуют как файлы в `01_3D` (для МОДИФИКАЦИЯ); сумма масс листа 1 ≈ масса сборки ±5 %.
- **Запуск:** Начальник КТО или технолог, вручную, из папки заказа:
  ```powershell
  python "Z:\00_ИНСТРУМЕНТЫ\_Инструменты_Конструктора\10_Свод_заявки\Свод_заявки.py" "Z:\03_ЗАКАЗЫ\250-АСТ_Школа12"
  ```
- **Ответственность:** технолог (ЕСТД, ГОСТ 3.1118) проверяет листы 1–5, Начальник КТО утверждает. Файл в `04_ПРОИЗВОДСТВО` — единственный документ для цехов, ОМТС и 1С.
- **ИИ:** допускается только для черновой выписки позиций из PDF служебной записки в `Разметка_СЗ.xlsx` с обязательной правкой человеком; данные заказчика во внешние сервисы не передаются без письменного соглашения о необработке. Google Antigravity и подобные среды разработки к производственному контуру не относятся.
- **Статус:** скрипт и шаблоны техкарт — задача инструментария ЕСКД (Д-47); до её закрытия свод выполняется технологом вручную по той же схеме листов.

## ПРИЛОЖЕНИЕ А. Скрипт `New-OrderFolder.ps1`

Хранится в `Z:\00_ИНСТРУМЕНТЫ\Шаблоны_заказа\`. Создаёт дерево заказа и изделия по §1.2, копирует шаблоны, проверяет длину пути. Повторный запуск безопасен (существующие папки не трогает).

```powershell
<#
.SYNOPSIS  Создаёт каноническую папку заказа КТО и (при -Product) папку изделия.
.EXAMPLE   .\New-OrderFolder.ps1 -Number 250-АСТ -Object Школа12
.EXAMPLE   .\New-OrderFolder.ps1 -Number 250-АСТ -Object Школа12 -Product "И01_Стол_L1400" -Designation "250-АСТ-Т01.00"
#>
param(
    [Parameter(Mandatory)] [string] $Number,        # номер заказа, например 250-АСТ
    [Parameter(Mandatory)] [string] $Object,        # объект, например Школа12
    [string] $Product,                              # папка изделия: И01_Стол_L1400
    [string] $Designation,                          # обозначение изделия: 250-АСТ-Т01.00
    [string] $Root = "Z:\03_ЗАКАЗЫ",
    [string] $Templates = "Z:\00_ИНСТРУМЕНТЫ\Шаблоны_заказа",
    [int]    $MaxPath = 200
)
$ErrorActionPreference = "Stop"
foreach ($s in @($Number, $Object, $Product)) {
    if ($s -and ($s -match '[\s\.]')) { throw "Имя «$s» содержит пробел или точку — запрещено §1.2." }
}
$order = Join-Path $Root "${Number}_${Object}"
$tree  = @("00_Исходные", "01_Корпус", "02_Металл")
foreach ($d in $tree) { New-Item -ItemType Directory -Force -Path (Join-Path $order $d) | Out-Null }
foreach ($t in @("Разметка_СЗ.xlsx", "Журнал_изменений.xlsx")) {
    $dst = Join-Path $order $t
    if (-not (Test-Path $dst)) { Copy-Item (Join-Path $Templates $t) $dst }
}
Write-Host "[OK] Заказ: $order"

if ($Product) {
    if (-not $Designation) { throw "Для изделия укажите -Designation (обозначение, например 250-АСТ-Т01.00)." }
    $prod = Join-Path (Join-Path $order "02_Металл") $Product
    foreach ($d in @("01_3D", "01_3D\Покупные", "01_3D\_Мастер", "02_PDF", "03_ЧПУ", "04_Тех", "_Аннулировано")) {
        New-Item -ItemType Directory -Force -Path (Join-Path $prod $d) | Out-Null
    }
    $card = Join-Path $prod "Техкарта_${Designation}_на_1шт.xlsx"
    if (-not (Test-Path $card)) { Copy-Item (Join-Path $Templates "Техкарта_на_1шт.xlsx") $card }
    # запас на имя файла модели (обозначение + наименование + расширение) ≈ 60 символов
    $longest = (Join-Path $prod "01_3D\Покупные\").Length + 60
    if ($longest -gt $MaxPath) { Write-Warning "Полный путь к файлам достигнет $longest символов (> $MaxPath). Сократите имя изделия." }
    Write-Host "[OK] Изделие: $prod"
}
```

Требования к шаблонам в `Шаблоны_заказа\`: `Разметка_СЗ.xlsx` (лист «Позиции» по §5.1 с выпадающими списками), `Журнал_изменений.xlsx` (листы «Ревизии», «Замечания»), `Техкарта_на_1шт.xlsx` (5 листов по §5.2).
