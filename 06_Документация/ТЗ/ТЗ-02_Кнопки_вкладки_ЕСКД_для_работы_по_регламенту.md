## 1. Цель

Восемь новых кнопок на вкладке «ЕСКД» надстройки, которые выполняют за конструктора, куратора баз и Начальника КТО ручные операции регламента: отвязку заимствованных деталей с чертежом, экспорт файлов для производства, проверку изделия, ведомость на изделие, сводную заявку и выдачу заказа в цех, закрытие заказа, новую ревизию, снимок эталона. Всё, что кнопки пишут в свойства моделей, совпадает с записью MProp (правило К-1 плана согласования). Битрикс24 не используется. История изменений изделия живёт в его папке.

| `Изменения.xlsx` | журнал в папке изделия или эталона; строки дописывают К-7 и К-8; человек не ведёт |

## 4. Архитектурные решения

| № | Решение | Почему |
| :---: | :--- | :--- |
| Р-1 | Один сервис на кнопку в `Sw/`; логика без SolidWorks — в `Core/` под юнит-тесты | как `SyncService`/`BchService` |
| Р-2 | Запись свойств — только через `PropertyWriter`; имена — только из `PropertyDictionary`; новые имена добавляются в словарь, не в код | правило К-1; существующий тест |
| Р-3 | XLSX читается и пишется через `System.IO.Packaging` (`WindowsBase.dll`, в составе .NET 4) без сторонних библиотек и без Excel | `build.ps1` без NuGet; Office на ПК не гарантирован |
| Р-4 | Кнопки пишут только в папки изделия, заказа, эталона, `04_ПРОИЗВОДСТВО`, `Y:` | регламент, ТЗ-01 «движок не пишет в источник» |
| Р-5 | Кнопки видят только текущий заказ и `02_БАЗА`; поиска по диску нет | скорость, предсказуемость |
| Р-6 | Сводная заявка считается из ведомостей изделий, модели при этом не открываются; ведомость эталона — обязательный файл в базе | стандартные изделия посчитаны один раз; выдача не зависит от открытия десятков сборок на `Z:` |
| Р-7 | Роль пользователя (конструктор / куратор баз / Начальник КТО / технолог) — в `ESKD_Settings`, задаётся установщиком по группе NAS (ТЗ-01 §5.5) или в «Настройках ЕСКД»; ограничение по роли — защита от ошибки | права на папки даёт NAS |
| Р-8 | Битрикс24, служебная записка отдела продаж, ЛЛМ — не используются | решения заказчика 15.09 |
| Р-9 | Ведомость изделия формирует **SWTools** по пресету «ЛЗК» (шаблон + имена свойств SWplus); надстройка ЕСКД экспорт спецификации не дублирует. К-4 запускает пресет SWTools и проверяет результат; К-5 читает ведомость по именованным диапазонам/заголовкам. Недостающее (запуск пресета из командной строки, площадь под покраску, длина заготовки) дорабатывается в SWTools отдельной задачей в его репозитории | у заказчика есть свой инструмент с исходниками (§3.5); две реализации BOM разойдутся |

## 5. Требования

### 5.1. Общие

| № | Требование |
| :---: | :--- |
| Т-1 | Вкладка «ЕСКД»: 3 существующие кнопки + 8 новых; `CommandUserIds` — 12 идентификаторов подряд (9900–9911); порядок: Настройки, Синхронизировать, Деталь БЧ, Сделать независимым с чертежом, Экспорт для производства, Проверить изделие, Ведомость изделия, Новая ревизия, Снимок эталона, Выдать в производство, Закрыть заказ |
| Т-2 | У каждой кнопки enable-метод: по типу документа, по папке документа (заказ / `02_БАЗА` / другое), по роли (Р-7). Недоступная кнопка серая, при наведении — причина |
| Т-3 | Кнопка перед работой проверяет занятость файлов (`~$`, попытка открыть на запись); при занятости — отказ с перечнем и именем пользователя из `~$` |
| Т-4 | Долгие операции показывают ход в строке состояния SolidWorks и пишут в `%TEMP%\eskd_material_sync.log` |
| Т-5 | Каждая кнопка заканчивается отчётом на экране (окно с текстом и кнопкой «Копировать») и файлом отчёта в папке, где работала |
| Т-6 | Кнопки не меняют геометрию, конфигурации и ссылки моделей, кроме явно указанных операций |
| Т-7 | Имена файлов и папок по регламенту; запрещённые символы Windows → `_`; длина пути проверяется до 240 символов |
| Т-8 | Существующие тесты (`static` 30, `unit`, E2E плана согласования) остаются зелёными; новых свойств в моделях не появляется, кроме добавленных по §5.3 |
| Т-9 | COM-метод на каждую кнопку для вызова без интерфейса (по образцу `SyncActiveDocumentSilent`): код и текст отчёта; используется E2E |

## 6. Ограничения исполнителю

1. Не менять `PropertyWriter`, `SyncService`, `BchService`, `SwPlusFormat`, кроме добавления вызовов; новые сервисы — отдельными файлами в `Sw/` и `Core/`.
2. Не добавлять сторонние библиотеки и NuGet; XLSX — через `WindowsBase.dll` (Р-3), ссылка добавляется в `build.ps1:45`.
3. Имена свойств — только из словаря через `PropertyDictionary`; литералов имён в вызовах записи нет.
4. Макросы SWplus не менять, кроме DProp для полей таблицы изменений (Т-15), если спайк С-3 покажет, что иначе нельзя; такое изменение — отдельный коммит с приёмкой К-1.
4а. SWTools менять только в его репозитории (`swtools/`, свои правила `CLAUDE.md`, `VERSION`, `scripts/workspace.ps1 -Action Status` = PASS) отдельными коммитами; из репозитория инструментария ЕСКД код SWTools не копировать.
5. E2E — только при закрытом SolidWorks; T0/T1 — в любое время.
6. Коммиты — по кнопкам, на ветке `feature/tz02-eskd-buttons`, с трейлером соавторства; в `refactor/v6-eskd` напрямую не коммитить.
7. Кнопки не пишут вне папок Р-4; в общую папку инструментария — никогда.
