## 1. Цель

Восемь новых кнопок на вкладке «ЕСКД» надстройки, которые выполняют за конструктора, куратора баз и Начальника КТО ручные операции регламента: отвязку заимствованных деталей с чертежом, экспорт файлов для производства, проверку изделия, СЗ на производство, выдачу заказа в цех, закрытие заказа, новую ревизию, снимок эталона. Всё, что кнопки пишут в свойства моделей, совпадает с записью MProp (правило К-1 плана согласования). Битрикс24 не используется. История изменений изделия живёт в его папке.

## 3. Исходное состояние (проверено по коду 15.09.2026)

### 3.1. Надстройка

- `SwAddin.cs:27` — `CommandUserIds = { 9900, 9901, 9902, 9903 }`; `SwAddin.cs:101–135` — `CreateCommands`: пустой элемент-разделитель и три кнопки «Настройки ЕСКД», «Синхронизировать», «Деталь БЧ» через `AddCommandItem2` с callback/enable-методами. Вкладка сверяет свои кнопки при загрузке и пересоздаётся при расхождении (коммит `553559f`).
- COM-методы для внешних вызовов: `SyncActiveDocumentSilent` (`:301`), `ToggleDrawinglessSilent` (`:440`), `DiagnoseActiveDocument` (`:457`), `GetVersion` (`:481`).
- `Sw/SyncService.cs`: `SyncModel(app, doc, SyncRequest)` (`:64`) — реквизиты, подписи, материал, масса; `SyncExplicit` (`:695`); `ReferencedModel(DrawingDoc)` (`:707`); `SyncMaterials` (`:404`), `SyncMass` (`:564`).
- `Sw/PropertyWriter.cs` — единственная точка записи свойств: `Set`, `SetIfEmpty`, `Delete` (`:185–223`), чтение `Raw`, `Resolved`, `NamesAt`. Статический тест `test_T0_addin_code_has_no_legacy_alias_writes` (`09_Тесты/tests/test_static.py:191`) ищет литералы имён в вызовах записи по всем исходникам.
- `Sw/BchService.cs`: `IsBch`, `BodyDimensions` (`:270`) — габариты тела; `Core/NameParsing.cs` — обозначение и наименование из имени файла; `Core/MaterialCatalog.cs`, `Core/MaterialRecord.cs` — библиотека и запись материала; `Core/SwPlusFormat.cs` — формат значений «как MProp».
- `Core/Settings.cs:12–30` — ветка `HKCU\Software\SolidWorks\ESKD_Settings`: `Author`, `Checker`, `Organization`, флаги синхронизации, `DictionaryPath`. Полей для ролей, коэффициентов, параметров экспорта нет.
- Сборка: `build.ps1` — системный `csc` .NET Framework 4, C# 5, ссылки `System`, `System.Drawing`, `System.Windows.Forms`, `System.Xml` и interop SolidWorks (`build.ps1:45`). NuGet и сторонних библиотек нет.

## 4. Архитектурные решения

| № | Решение | Почему |
| :---: | :--- | :--- |
| Р-1 | Один сервис на кнопку в `Sw/`; вся логика без SolidWorks — в `Core/` под юнит-тесты | как сделано для `SyncService`/`BchService`; `Core` тестируется без SolidWorks |
| Р-2 | Запись свойств — только через `PropertyWriter`; имена свойств — только из `PropertyDictionary`; новые имена добавляются в словарь, а не в код | правило К-1; тест `test_T0_addin_code_has_no_legacy_alias_writes` |
| Р-3 | XLSX читается и пишется через `System.IO.Packaging` (`WindowsBase.dll`, входит в .NET 4) без сторонних библиотек и без Excel | `build.ps1` без NuGet; Excel на ПК конструктора не гарантирован |
| Р-4 | Файлы выдачи, отчёты и журналы — только в папках изделия, заказа, эталона, `04_ПРОИЗВОДСТВО`, `Y:`; вне этих папок кнопки не пишут | регламент, ТЗ-01 «движок не пишет в источник» |
| Р-5 | Все кнопки видят только текущий заказ и `02_БАЗА`; поиска по всему диску нет | скорость, предсказуемость |
| Р-6 | Сопоставление шифров: нормализация (регистр, пробелы, дефис/тире, латиница↔кириллица для похожих букв); при неоднозначности — диалог выбора, ответ запоминается в служебной записке (скрытый столбец `Папка`) | опечатка — один клик, не сломанный заказ |
| Р-7 | Роль пользователя (конструктор / куратор баз / Начальник КТО / технолог) — в `ESKD_Settings`, задаётся установщиком по группе NAS (ТЗ-01 §5.5) или в «Настройках ЕСКД»; ограничение кнопок по роли — защита от ошибки, не от злого умысла | права на папки даёт NAS |
| Р-8 | Битрикс24 не используется. Место для ЛЛМ-сопоставления в К-5 — интерфейс `IOrderMatcher` с реализацией по Р-6; ЛЛМ-реализация — вне рамок (ТЗ-03 по решению заказчика) | решение заказчика 15.09 |

## 5. Требования

### 5.1. Общие

| № | Требование |
| :---: | :--- |
| Т-1 | Вкладка «ЕСКД»: 3 существующие кнопки + 8 новых; `CommandUserIds` расширяется до 12 идентификаторов подряд (9900–9911); порядок: Настройки, Синхронизировать, Деталь БЧ, Сделать независимым с чертежом, Экспорт для производства, Проверить изделие, СЗ на производство, Новая ревизия, Снимок эталона, Выдать в производство, Закрыть заказ |
| Т-2 | Каждая кнопка имеет enable-метод: по типу документа (деталь/сборка/чертёж), по папке документа (заказ / `02_БАЗА` / другое), по роли (Р-7). Недоступная кнопка серая, при наведении — причина |
| Т-3 | Кнопка перед работой проверяет, что нужные файлы не открыты другими: `~$`-файлы и попытка открыть на запись; при занятости — отказ с перечнем файлов и именем пользователя из `~$` |
| Т-4 | Долгие операции (обход сборки, экспорт, копирование) показывают ход в строке состояния SolidWorks и пишут в `%TEMP%\eskd_material_sync.log` |
| Т-5 | Каждая кнопка заканчивается отчётом на экране (окно с текстом, можно скопировать) и записью отчёта в файл в папке, где работала |
| Т-6 | Кнопки не меняют геометрию, конфигурации, ссылки моделей, кроме явно указанных операций (К-1: «Сделать независимым», замена ссылок чертежа) |
| Т-7 | Все имена файлов и папок по регламенту: `<Обозначение> <Наименование>.<расш>`; запрещённые символы Windows заменяются на `_`; длина пути проверяется до 240 символов |
| Т-8 | Существующие тесты (`static` 30, `unit`, E2E плана согласования) остаются зелёными; новых свойств в моделях не появляется, кроме добавленных в словарь по §5.3 |
| Т-9 | COM-метод на каждую кнопку для вызова без интерфейса (по образцу `SyncActiveDocumentSilent`): возвращает код и текст отчёта; используется E2E-тестами |

### С-5. Как узнать деталь из листа и из профиля — проверено на 89 типовых деталях

| Признак | Деталей | Что читается |
| :--- | ---: | :--- |
| Листовой металл (`SheetMetal`/`FlatPattern`) | 16 | толщина — `SheetMetalFeatureData.Thickness`; список вырезов: «Длина/Ширина/Площадь граничной рамки», «Толщина листового металла», «Cutting Length-Outer/Inner», «Сгибы» |
| Сварной профиль (`WeldMemberFeat`, `WeldmentFeature`) | 17 | список вырезов: `LENGTH`/`ДЛИНА`, `ANGLE1/2`/`УГОЛ1/2`, `SORTAMENT`, `QUANTITY`, `Material`; имя профиля через `GetDefinition.ProfileName` пустое — брать из `SORTAMENT` |
| Размер `RD1@Примечания` | 20 (11 — у сварных профилей, 9 — у других) | длина заготовки по регламенту |
| Система координат (любая, в том числе `Труба`) | **0** | — |
| Многотельные | 3 | — |

- **Решение для Э3:** «лист» — есть элемент `SheetMetal`; «профиль» — есть `WeldMemberFeat` (или элемент списка вырезов с `LENGTH`); длина — `LENGTH` списка вырезов, иначе `RD1`, иначе габарит с пометкой; толщина — из листового металла.
- **Т-29 пересмотреть:** СК `Труба` у конструкторов не используется. Для IGS нужна договорённость: кнопка создаёт временную СК по оси профиля (по `WeldMemberFeat`) или конструктор строит профиль вдоль оси — решение технолога после пробного импорта в CypTube.
- **Возможная ошибка в профиле:** у `ТС1.02.001 Патрубок` профиль «ТРУБА 114Х6», а `SORTAMENT` вычисляется как «Труба **108**х6 ГОСТ 8732-78» (выражение берёт размер `Dвн`); у труб 133×6 и 140×10 значение совпадает с профилем. Нужно проверить профиль 114×6 в `04_…\Профили сварных деталей` до Э3: по неверному `SORTAMENT` будут неверными имя файла ЧПУ и СЗ.
- Толщина 250 мм у `ТС3.03.00.019 Платик` — вероятно, ошибка модели; кнопка «Проверить изделие» должна предупреждать о толщине листа больше 50 мм.
- Фикстуры корпуса A — простые вытяжки без листового металла и сварных профилей: для E02/E04 нужен стенд с реальными деталями (копии из типовых сборок).
