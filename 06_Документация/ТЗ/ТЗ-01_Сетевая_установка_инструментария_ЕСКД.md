## 1. Цель

Инструментарий ЕСКД хранится в одной общей папке на NAS. Конструктор настраивает свой ПК так:

1. открывает `Z:\00_ИНСТРУМЕНТЫ\_Инструменты_Конструктора\01_Настройки_SolidWorks\Настройка_Рабочего_Места_SolidWorks.exe` двойным щелчком;
2. проверяет фамилию и организацию;
3. нажимает «Установить / Обновить».

Всё, что обязано существовать на ПК локально, конфигуратор создаёт и поддерживает сам:

- отдельную ветку реестра установки для каждого пользователя;
- отдельный локальный экземпляр того, что нельзя запускать с сети без конфликтов: надстройку ЕСКД и те макросы SWplus, которые при одновременной работе нескольких конструкторов ломаются или мешают друг другу;
- регистрацию надстройки, пути SolidWorks, кнопки SWplus, шрифты, Drew.

**Макросы SWplus по умолчанию запускаются с сетевого диска.** Локальную копию получает только макрос, для которого спайк С-1 доказал конфликт при многопользовательской работе (§5.4).

Повторный запуск конфигуратора обновляет ПК до выпуска, опубликованного в общей папке. В общую папку конфигуратор не пишет никогда.

## 4. Архитектурное решение Р-1: один движок, конфигуратор — окно

**Решение по умолчанию.** Всю работу с реестром и файлами выполняет движок на PowerShell. Конфигуратор собирает данные и выбор пользователя, запускает движок, показывает ход и итог. Сам конфигуратор реестр и файлы ПК не меняет.

**Обоснование.**

1. Две реализации уже разошлись (§3.1), и каждая исправленная ошибка приходится делать дважды.
2. У PowerShell-установщика есть автотесты T0, общий модуль регистрации с тестовыми корнями реестра, резервная копия реестра и безопасное закрытие SolidWorks.
3. Функции, которые есть только в конфигураторе (RealView, Dynamic Highlight, экспорт профиля, полный сброс), переносятся в движок и становятся проверяемыми.

**Альтернатива Р-1Б.** Движок на Python внутри конфигуратора, PowerShell-установщик удаляется. Цена: переписать на Python регистрацию, резервную копию, закрытие SolidWorks и перевести тесты T0. Заказчик может выбрать Р-1Б **до начала этапа Э1**; тогда требования §5 сохраняются, меняются только файлы, где они реализуются.

**Чего не переносить из текущего конфигуратора:** вставку фамилии и организации в начало списков (К-4), `taskkill /F` без подтверждения, регистрацию шрифтов на сеанс (К-8), запасной путь `D:\Work`, мёртвые флажки, текст «центрирование массы в штампе» в описании надстройки (строка 584, утверждение v5).

### 5.4. Размещение макросов SWplus и локальный экземпляр

**Правило размещения.** Макрос — сетевой, если при проверке С-1 выполнены все условия:

1. при обычной работе он не создаёт, не изменяет и не удаляет файлы в папке макросов и в общих папках (`Основные надписи`, справочники);
2. он работает, когда у пользователя на папку макросов права только на чтение;
3. два пользователя на разных ПК запускают его одновременно без ошибок и без влияния на результат друг друга;
4. если он вызывает другой макрос, вызываемый тоже сетевой (связанные макросы размещаются одной группой).

Нарушено хотя бы одно условие — макрос локальный. Решение по каждому макросу записывается в матрицу с номером сценария С-1, который его обосновал.

### 5.5. Ветка установки в реестре

`HKCU\Software\SolidWorks\ESKD_Install` (в тестах — `<RegistryRoot>\SolidWorks\ESKD_Install`). Пишется в конце успешной установки; при ошибке — только `LastResult` и `LastError`.

| Значение | Тип | Содержимое |
| :--- | :--- | :--- |
| `SourceRoot`, `SourceRootUnc` | String | корень источника в записанной форме и в UNC |
| `LocalRoot` | String | раскрытый путь локального экземпляра |
| `ReleaseVersion`, `ReleaseCommit`, `ReleaseDate` | String | из `toolkit_release.json` |
| `EngineVersion`, `ConfiguratorVersion` | String | версии движка и конфигуратора (конфигуратор передаёт свою параметром) |
| `SwVersion` | String | например `SOLIDWORKS 2025` |

| `MacroPlacement` | MultiString | `MProp=network`, `Master=local`, … — фактическое размещение |

| `Machine`, `User` | String | `%COMPUTERNAME%`, `DOMAIN\user` |

### 5.6. Фаза пользователя: порядок шагов движка

1. Проверки: источник доступен; `toolkit_release.json` читается; SolidWorks закрыт по `-CloseMode`; свободно не менее 200 МБ в `%LOCALAPPDATA%`.
2. `Check`: сравнить ветку установки, хеши локального экземпляра и выпуск; отчёт и код выхода по Т-18; без изменений.
3. Резервная копия HKCU-веток SolidWorks и `AddInsStartup` (`Backup-SolidWorksRegistryKeys`, установщик 164–197) в `%LOCALAPPDATA%\ESKD\Backups\Backup_<дата>`; хранить последние 5.
4. Локальный экземпляр по §5.4: надстройка, служебная копия, локальные макросы.
5. Профиль реестра (если `-Profile`): адаптация по §5.3, временный файл в `%TEMP%`, `reg.exe import` с проверкой кода; при `-RegistryRoot` ≠ HKCU — запись через провайдер реестра в тестовый раздел.
6. Функции конфигуратора, перенесённые в движок: RealView по списку видеокарт (`-RealView`), Dynamic Highlight (`-DynamicHighlight`), `Use Performance Pipeline 2020` = 0.
7. Очистка устаревших надстроек и вкладок (установщик 325–422, 543–651) — только HKCU.
8. Кнопки SWplus (если `-SwPlusButtons`): `User Defined Macros` по матрице, QAT, `Menu Customizations`.
9. Надстройка ЕСКД (если `-EskdAddin`): `Register-EskdAddin -DllPath <LocalRoot>\03_Макросы_и_Плагины\ESKD_Material_Sync_Addin\ESKD_Material_Sync_v5.dll -UserRoot <RegistryRoot>` без `-SystemWide`; вкладка ЕСКД, избранные материалы, `ESKD_Settings`.
10. Пути класса П: `Toolbox Data Location` в HKCU, Design Library. Недоступный путь площадки — `WARN`, значение не пишется.
11. Шрифты (если `-Fonts`): если в системе нет — установка в профиль пользователя (установщик 880–884), постоянная, без администратора.
12. Drew (если `-Drew`): если нет в `Program Files` и `%LOCALAPPDATA%` — установка в `%LOCALAPPDATA%` существующим `install-all.ps1` в режиме пользователя (по С-4); регистрация HKCU на установленную DLL. Загрузка Drew из источника запрещена.
13. Ветка установки (§5.5). Отчёт `%LOCALAPPDATA%\ESKD\Logs\setup_<дата>.log` и `.json`; событие `result`.
14. Если нужна фаза машины (§5.7) — событие `log` уровня `WARN` с текстом для кнопки «Системные компоненты…».
