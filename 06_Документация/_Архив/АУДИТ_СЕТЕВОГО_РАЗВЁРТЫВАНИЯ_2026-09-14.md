## 3. Данные SolidWorks с сетевой папки «только чтение»

### 3.1. Что SolidWorks делает с такими файлами

- **Шаблоны** (`.prtdot/.asmdot/.drwdot`) SolidWorks только читает при «Создать»; новый документ никак не связан с шаблоном. Права записи не нужны.
- **Основные надписи** (`.slddrt`) читаются при создании листа и при «Перезагрузить формат»; после этого форматка встроена в чертёж. Права записи не нужны. Исключение — макрос Master, который **создаёт** `.slddrt` в этой папке (5.5).
- **Стандарт оформления** (`.sldstd`) читается при загрузке в документ. Права записи не нужны.
- **Библиотека материалов** (`.sldmat`): SolidWorks показывает базу, к которой нет записи, с замком и не даёт добавлять в неё материалы — для корпоративной библиотеки это желаемое поведение. Личные материалы пользователь по-прежнему кладёт в «Настроенный пользователем материал» (`C:\ProgramData\…`, есть в `Material Database Folders` на этом ПК). Что делает SolidWorks при **замене** `.sldmat` на сети во время работы (кэширует, держит открытым, читает заново) — по коду не установить, это спайк С-5 ТЗ-01.
- **Профили** (`.sldlfp`) и вкладки свойств (`.prtprp`) только читаются. В `.prtprp` путей нет (проверено: `default.prtprp`, `Деталь.prtprp`, `Деталь_ГОСТ.prtprp`), значит их можно раздавать с любой папки.
- **Макросы** (`.swp`) SolidWorks читает при запуске; специального «доверенного расположения» для макросов, как в Office, у SolidWorks нет. Работу `RunMacro` с UNC-пути и с буквы диска подтвердить на стенде (С-1, сценарий 5).

### 3.2. Атрибут «только для чтения» и права NTFS — не одно и то же

Атрибут файла останавливает `Open … For Output` в VBA (ошибка 75) и запись из надстройки, но:

- на **папке** атрибут ничего не запрещает (Windows использует его для «настроенных» папок), новые файлы в ней создаются свободно — Master создаст свои `.slddrt`, надстройка — резервные копии;
- любой пользователь с правом записи может снять атрибут, SolidWorks при сохранении «Сохранить как» в такую папку предложит это сделать.

Нужны **права NTFS и общего ресурса**: конструкторам — «Чтение и выполнение», администратору — «Изменение». Тогда атрибут не нужен, а ошибки доступа однозначны. Регламент §2.3 (п. 4) это уже предполагает.

### 3.3. Буква диска или UNC

SolidWorks принимает оба вида путей. Но установщик подставляет корень только в путях вида `X:\…\_Инструменты_Конструктора` — регулярное выражение `Setup_Workstation_SolidWorks.ps1:503` начинается с `[A-Za-z]:`; корень `\\сервер\ресурс\…` он не распознает и оставит в профиле `d:\Work\…`. Пока установщик не переписан по ТЗ-01, папка должна быть подключена буквой диска у каждого пользователя. Вторая причина в пользу буквы: имя общего ресурса на этом ПК уже кириллическое (`\\<ПК>\Инструменты_Конструктора`), а регистрация надстройки с кириллицей в пути и так на особом положении (DEP-11, `Register-EskdAddin.ps1:16-17`).

Оборотная сторона буквы диска: у процесса с повышенными правами подключённого диска обычно нет (`EnableLinkedConnections` на этом ПК не задан), а `УСТАНОВИТЬ_ЕСКД.bat:6-11` всегда повышает права. Это спайк С-3 ТЗ-01.

### 3.4. Шрифты

Шрифт — единственные «данные», которые с сети не работают: SolidWorks берёт шрифты из Windows. `GOST 2.304 type A` (`05_Шрифты/GOST2304A_1.ttf`) должен быть установлен на каждом ПК системно (нужен администратор) или в профиль пользователя (`Setup…ps1:874-884` умеет). На этом ПК он установлен системно (`HKLM\…\Fonts`: `GOST2304A_1 (TrueType)`).

### 3.5. Параметры SolidWorks для совместной работы

В профиле `.reg` есть `DoNotSaveReadOnlyDocs=1` и настройки резервных копий (`Backup Copies`, `Backup to original path=0`), но **нет** параметров «Совместная работа» (`Enable multi-user environment`, проверка изменений файлов только для чтения) и «Открывать ссылочные документы только для чтения» — регламент §2.4 велит выставлять их руками (строки 242-248). Их стоит внести в профиль, чтобы они ставились установкой; это правка `.reg`, не кода.

### 3.6. Отклонение на этом ПК

В живом реестре `Drafting Standard Folder` указывает на подпапку `02_Шаблоны_и_Форматки`, которой **нет** (значение времён v5); в профиле `.reg` тот же параметр указывает на `…\SWPlusMacro_v_2018_SP0.0\SpecEditor` (где лежит `MyStandard.sldstd`). Также `BOM Template Folders` и `Hole Table Template Folders` содержат `D:\dev\OnCadTools\模板` — остаток чужой надстройки; в профиль `.reg` он не попал. Это ПК разработчика, для тиража значения не имеет, но показывает, что «живой» реестр и профиль расходятся: эталон — профиль.

### 3.7. Обновление данных при работающих пользователях

Замена шаблонов, форматок, стандарта и профилей на сети во время работы безопасна: SolidWorks читает их в момент использования. Библиотека материалов — спайк С-5. Макрос `.swp` заменять, когда у кого-то открыта его форма, не стоит. DLL надстройки — только при закрытых SolidWorks, потому она и не должна лежать на сети (4.1).

## 4. Надстройка ЕСКД

### 4.1. Почему DLL не может лежать в сетевой папке

1. **Блокировка.** SolidWorks держит DLL открытой всё время работы. Если DLL общая, обновить её нельзя, пока хоть у кого-то открыт SolidWorks; `build.ps1:24-31` проверяет только локальный `SLDWORKS.exe`.
2. **Загрузка .NET с сети.** CodeBase регистрации — путь к файлу (`Register-EskdAddin.ps1:45-49,104`), на этом ПК `file:///D:/Work/…`. CLR .NET Framework 4 отказывается загружать сборку из сетевого расположения (`NotSupportedException`, «assembly from a network location») без ключа `loadFromRemoteSources` в конфигурации **процесса** — а процесс здесь `SLDWORKS.exe`, его `.config` принадлежит SolidWorks. То же касается `Assembly.LoadFrom` интеропов в `SwAddin.cs:39-52`. Проверить на стенде (новый спайк С-8), но рассчитывать на удачу нельзя.
3. **Интеропы.** `SolidWorks.Interop.*.dll` копируются в папку надстройки из SolidWorks **того ПК, где шла сборка** (`build.ps1:34-44`), и загружаются оттуда у всех (`SwAddin.cs:34-52`). При общей папке все ПК получают интеропы одной версии, а любая пересборка на одном ПК подменяет их всем.
4. **Регистрация с кириллицей.** RegAsm не используется: CLR не активирует %-кодированный CodeBase с кириллицей (DEP-11). UNC-путь с кириллическим именем ресурса — тот же класс проблем, спайк С-8.
5. **Сборка при установке.** `Setup…ps1:685` собирает DLL на каждом ПК из исходников; DLL и exe в git не хранятся (`.gitignore:31-37`). На сетевой папке без права записи сборка невозможна, а с правом — каждый ПК перезаписывает общую DLL. ТЗ-01 Т-30 правильно требует: на ПК не собирать, выпуск публикует администратор.

**Вывод:** DLL, `ESKD.exe`, `ESKD_Sync.exe`, `ESKD.ico`, `Icons\`, три интеропа — локальная копия (ТЗ-01 Т-22, Т-23), регистрация HKCU на неё.

### 4.2. Что надстройка ищет «вверх от DLL» и что с этим станет при локальной копии

### 4.5. Что уже сделано правильно

- Регистрация — единый модуль `Register-EskdAddin.ps1` с параметрами `-UserRoot`/`-MachineRoot`, HKCU без администратора; ТЗ-01 §5.6 п. 9 использует его как есть.

### 4.6. Утилиты `ESKD_Sync.exe /clean` и `/reloadformats`

Работают через уже запущенный SolidWorks (`Program.cs:52,177`), открывают и сохраняют документы **проекта** — то есть общие рабочие файлы на сети. Проверка «документ открыт в SolidWorks» (`MigrationService.cs:134`, `FormatReloadService.cs:113`) видит только SolidWorks этого ПК; документ, открытый коллегой, будет пересохранён под ним. Правило: эти утилиты запускает администратор, когда у всех SolidWorks закрыт; резервная копия ложится рядом с проектом. Форматки поставки для `/reloadformats` ищутся только вверх от exe (4.2) — при локальной копии надстройки нужен параметр пути (А-3).

### 5.1. Общие свойства набора

- **Пути только относительные** — от `swApp.GetCurrentMacroPathName` отрезанием фиксированного числа символов: DProp `FrmDProp.frm.txt:220-230` (−15 = `DProp\DProp.swp`), Master `FrmMaster.frm.txt:79-96` (−17), MProp `FrmMProp.frm.txt:1291-1309` (−15), SpecEditor `FrmSpecEditor.frm.txt:980-999` (−14), SProp `FrmSProp.frm.txt:408-414` (−15). Следствие: папка SWPlus переносится целиком, **имена `.swp` и глубина папок менять нельзя**; сама сеть им безразлична.
- **Единственный абсолютный путь** — `Master\Master.ini`, строка 4: `D:\Work\_Инструменты_Конструктора\…\Основные надписи\`. Его читают Master (`FrmMaster.frm.txt:147`) и **DProp** (`FrmDProp.frm.txt:250`, используется в `:510,1408-1417` для имён `.slddrt`). - **Реестр макросы не используют** (ни `GetSetting`, ни `SaveSetting`): всё состояние в файлах рядом с макросом. **`%TEMP%` не используют**: временные файлы тоже создаются рядом.
- **Настройки положительно-позиционные** (`.ini` без секций и ключей): частично записанный файл молча ломает все последующие поля.
- **Макросы вызывают друг друга по соседним папкам** (`RunMacro` по пути): DProp → `..\MProp\MProp.swp` (`FrmDProp.frm.txt:223,550`), → `..\Master\Master.swp` (`:222,425,489`), → `..\Roughness\Roughness.swp` (`:224,552`); MProp → SProp (`FrmMProp.frm.txt:1300,1823`); все окна настроек → `..\SpecEditor\MyProperties.swp`. Значит MProp, DProp, SProp, SpecEditor, Master, MyProperties размещаются **одной группой** (ТЗ-01 СВ-2).
- **Notepad без кавычек**: `Shell("Notepad " & путь)` в `FrmMProp.frm.txt:3401`, `FrmMProp_Pref.frm.txt:27,32,37`, `FrmSpecEditor_Pref.frm.txt:47,52,62`, `FrmSpecEditor_Doc.frm.txt:102`, `FrmSProp_Pref.frm.txt:19,24,29` — путь с пробелом (а `Инструменты Конструктора` или `Основные надписи` его содержат) открывает не тот файл.

- **Локальный Master с локальной копией «Основные надписи»** и `Sheet Format Folders` на локальную копию (ТЗ-01 Т-25). Минус: у каждого ПК своя папка форматок, обновление через выпуск.

Это работает, пока конструктор не попросит формат, которого нет в папке (например A0×2). Требует правки VBA только для понятного сообщения вместо ошибки `Kill`/`Name`.

### 5.6. ТТ, SaveAsPDF, `TT.EXE`, справка

- `TT.EXE` — родной исполняемый файл в папке макросов. Запуск с сетевого пути даёт предупреждение «Открыть файл — предупреждение системы безопасности» (зона «Интранет»), пока зона не в доверенных или файл не локальный.
