## 2. Архитектура COM-сервера и жизненный цикл обработки событий

### 2.1. Точка входа COM: `SwAddin.cs`
Класс `SwAddin` реализует стандартный интерфейс расширений SolidWorks:
```csharp
[Guid("B64E6875-B101-4D5C-B245-FF8D50772E25")]
[ComVisible(true)]
[ClassInterface(ClassInterfaceType.AutoDispatch)]
[ProgId("ESKD.MaterialSync.SwAddin_v5")]
public class SwAddin : ISwAddin
```

### 2.2. Инициализация и подключение (`ConnectToSW`)
При запуске SolidWorks загружает надстройку и вызывает метод `ConnectToSW(object ThisSW, int cookie)`:
1. **Регистрация обратного вызова**: `iSwApp.SetAddinCallbackInfo2(0L, this, cookie)`.
2. **Построение интерфейса CommandManager**:
   - Создается группа команд `CommandGroupId = 9997` с двумя кнопками: *«Настройки ЕСКД»* (вызов `ShowSettings`) и *«Синхронизировать свойства»* (вызов `SyncCurrentDoc`).
   - Для всех типов документов (`swDocPART`, `swDocASSEMBLY`, `swDocDRAWING`) в ленту инструментов добавляется вкладка `ЕСКД` (`tab.Visible = true`).
3. **Подписка на события уровня приложения (`AttachAppEvents`)**:
   ```csharp
   SldWorks app = (SldWorks)iSwApp;
   app.FileOpenPostNotify += OnFileOpenPost;
   app.FileNewNotify2 += OnFileNew2;
   app.ActiveDocChangeNotify += OnActiveDocChange;
   app.CommandCloseNotify += OnCommandClose;
   ```
4. **Подписка на события открытых документов (`AttachDocEvents`)**:
   Для каждого открываемого документа регистрируются хуки сохранения:
   - `PartDoc.FileSaveNotify` -> `OnDocFileSave`
   - `AssemblyDoc.FileSaveNotify` -> `OnDocFileSave`
   - `DrawingDoc.FileSaveNotify` -> `OnDocFileSave`
   - `ModelDoc2.DestroyNotify2` -> `OnDocDestroy` (для безопасной отписки и исключения утечек COM-дескрипторов).

> [!IMPORTANT]
> **Изоляция деструктивного события `RegenNotify`**:
> В ранних ревизиях надстройки событие перестроения чертежа `RegenNotify` приводило к каскадному сдвигу координат заметок штампа при каждом зумировании и регенерации листа. В текущей версии подписка на `RegenNotify` **полностью отвязана**, что устранило паразитный дрейф аннотаций.

## 3. Детальный аудит реализации ключевого функционала

### 3.1. Полная совместимость с макросом `MProp` (Синхронизация организации и разработчика)

#### Анализ исходного кода макроса MProp (`FrmMProp.frm`):
В коде макроса чтение организации осуществляется вызовом:
```vb
sConfigName = swModel.GetActiveConfiguration().Name
prpFirm = "Контора"
CboFirm.Value = swModel.CustomInfo2(sConfigName, prpFirm)
```
Вызов SolidWorks API `swModel.CustomInfo2(sConfigName, ...)` производит поиск свойства **исключительно в свойствах заданной конфигурации**. Если свойство записано только в общие свойства (`cpmGen`), в MProp выпадающий список оставался пустым.

#### Реализация в `MaterialSyncEngine.cs` (`ApplyUserSettings`, строки 715–824):
```csharp
// 1. Запись в общие свойства модели (cpmGen)
CustomPropertyManager cpmGen = model.Extension.get_CustomPropertyManager("");
if (cpmGen != null)
{
    SetProp(cpmGen, "Разраб.", author);
    SetProp(cpmGen, "Разработал", author);
    SetProp(cpmGen, "Конструктор", author);
    SetProp(cpmGen, "Контора", org);
    SetProp(cpmGen, "Организация", org);
    SetProp(cpmGen, "Организация_ФБ", org);
}

// 2. Сквозная запись во ВСЕ существующие конфигурации модели
string[] allConfigs = model.GetConfigurationNames() as string[];
if (allConfigs != null)
{
    foreach (string cfg in allConfigs)
    {
        CustomPropertyManager cpmCfg = model.Extension.get_CustomPropertyManager(cfg);
        if (cpmCfg != null)
        {
            SetProp(cpmCfg, "Разраб.", author);
            SetProp(cpmCfg, "Разработал", author);
            SetProp(cpmCfg, "Конструктор", author);
            SetProp(cpmCfg, "Контора", org);
            SetProp(cpmCfg, "Организация", org);
            SetProp(cpmCfg, "Организация_ФБ", org);
        }
    }
}
```
*Результат*: При открытии модели любой конфигурации в MProp поля `Разраб.` и `Контора` гарантированно заполнены актуальными данными.

### 3.3. Синхронизация штампа чертежа через модель первого вида (`$PRPSHEET`)

#### Физика работы штампа SolidWorks:
В шаблонах чертежей по ГОСТ 2.104 основные надписи используют выражения `$PRPSHEET`:
* Ячейка «Разраб.»: `$PRPSHEET:"Разраб."`
* Ячейка «Организация»: `$PRPSHEET:"Организация"`

Данные выражения опрашивают **3D-модель (деталь или сборку)**, отображаемую на чертеже, а не файл `.slddrw`. Модификация свойств только чертежа оставляла штамп неизменным.

#### Реализация в `MaterialSyncEngine.SyncDrawing` (строки 234–284):
```csharp
View v = (View)drw.GetFirstView();
if (v != null)
{
    // Получение первого проекционного вида с 3D моделью
    View refView = (View)v.GetNextView();
    if (refView != null)
    {
        ModelDoc2 refModel = (ModelDoc2)refView.ReferencedDocument;
        if (refModel != null)
        {
            string refCfg = refView.ReferencedConfiguration;
            // Сквозная передача настроек ЕСКД в ссылочную 3D модель
            ApplyUserSettings(refModel, refCfg, null, null);
            if (triggerRebuild)
            {
                drwModel.ForceRebuild3(false);
            }
        }
    }
}
```
*Результат*: При нажатии «Применить» или автосохранении чертежа реквизиты записываются непосредственно в исходную деталь/сборку, и штамп мгновенно обновляется.

### 3.4. Защита стандартных и покупных изделий (SProp & Toolbox)

#### Проблема:
При сохранении крепежа или покупных компонентов надстройка ЕСКД могла распарсить имя файла (например, `Винт М6х20 ГОСТ 11738-84.sldprt`), перезаписать наименование по каталогу поставщика, сбросить параметры покупного изделия или пересчитать массу.

#### Реализация предиката `IsStandardOrPurchasedPart` (строки 405–465):
```csharp
public static bool IsStandardOrPurchasedPart(ModelDoc2 model)
{
    if (model == null) return false;
    
    // 1. Проверка общих и конфигурационных свойств изделия
    CustomPropertyManager cpmGen = model.Extension.get_CustomPropertyManager("");
    if (cpmGen != null && CheckStandardPartProperties(cpmGen)) return true;

    Configuration activeConfig = (Configuration)model.GetActiveConfiguration();
    if (activeConfig != null)
    {
        CustomPropertyManager cpmCfg = model.Extension.get_CustomPropertyManager(activeConfig.Name);
        if (cpmCfg != null && CheckStandardPartProperties(cpmCfg)) return true;
    }

    // 2. Проверка расположения в папке SolidWorks Toolbox
    string pName = model.GetPathName();
    if (!string.IsNullOrEmpty(pName))
    {
        string lp = pName.ToLowerInvariant();
        if (lp.Contains("toolbox") || lp.Contains("solidworks data")) return true;
    }

    // 3. Проверка COM-объекта ToolboxPartInformation через рефлексию
    try
    {
        object ext = model.Extension;
        if (ext != null)
        {
            PropertyInfo pi = ext.GetType().GetProperty("ToolboxPartInformation");
            if (pi != null && pi.GetValue(ext, null) != null) return true;
        }
    }
    catch { }

    return false;
}
```

#### Метод `CheckStandardPartProperties`:
Идентифицирует стандартное изделие по наличию любого из критериев:
1. Свойство `Раздел` содержит: `стандартн`, `прочи`, `покупн`, `материал` или начинается с `эм-`;
2. Наличие флага `IsFastener` (крепеж);
3. Наличие каталожных свойств: `Наименование_ВП`, `Поставщик`, `Код_Продукции`, `Обозначение_ДНП`, `Справочный_номер_ВП`.

#### Защитный барьер в `SyncPart` (строка 488):
```csharp
if (IsStandardOrPurchasedPart(model))
{
    result.Success = true;
    result.Message = "Стандартное/покупное изделие (SProp): синхронизация пропущена";
    return result;
}
```
*Результат*: 100% гарантия сохранности реквизитов стандартных деталей при сохранении.

### 3.5. Исключение рекурсивного обхода сборок (Non-Recursive Assembly Sync)

#### Проблема:
Вызов `AssemblyDoc.GetComponents(false)` на сборках верхнего уровня, содержащих 5 000–50 000 компонентов, приводит к зависанию SolidWorks на несколько минут при каждом нажатии `Ctrl+S`.

#### Реализация в `SyncAssembly` (строки 208–224):
```csharp
public static void SyncAssembly(AssemblyDoc asm, ISldWorks swApp, bool force = false, string targetFileName = null)
{
    if (asm == null || swApp == null) return;
    if (!force && !IsServiceEnabled()) return;
    try
    {
        ModelDoc2 model = (ModelDoc2)asm;

        // STRICT RECURSION GUARD:
        // Обрабатывается ТОЛЬКО сам файл корневой сборки.
        // Вызовы asm.GetComponents() КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНЫ!
        Configuration activeConfig = (Configuration)model.GetActiveConfiguration();
        string cfgName = activeConfig != null ? activeConfig.Name : "";
        MaterialSyncResult res = new MaterialSyncResult();
        ApplyUserSettings(model, cfgName, res, targetFileName);
    }
    catch { }
}
```
Масса сборки вычисляется через нативный объект ядра SolidWorks:
```csharp
MassProperty massProp = (MassProperty)model.Extension.CreateMassProperty();
```
Вычисление выполняется внутренним физическим движком САПР без итерации по COM-дереву компонентов.

### 3.6. Ликвидация дрейфа надписей штампа (Zero-Drift Mechanism)

#### Коренная причина дрейфа:
В устаревших версиях надстройки существовали методы `AlignDrawingMassNote`, `AlignDrawingMaterialNote`, `AlignDrawingTitleNote`, которые при сохранении чертежа пытались принудительно пересчитать координаты $X, Y$ заметок штампа на основе габаритов листа. Из-за округления чисел с плавающей точкой в COM API заметки смещались на 0.1–0.5 мм при каждом сохранении.

#### Архитектурное решение:
1. Все смещающие методы нейтрализованы в безопасные no-op вызовы:
   ```csharp
   public static void RestoreDrawingStampTemplate(DrawingDoc drw) { }
   public static void AlignDrawingMassNote(DrawingDoc drw) { }
   public static void AlignDrawingMaterialNote(DrawingDoc drw) { }
   public static void AlignDrawingTitleNote(DrawingDoc drw) { }
   public static void AlignSpecificationTableColumns(DrawingDoc drw) { }
   ```
2. Координаты заметок штампа зафиксированы на уровне эталонных форматок `.slddrt`.
3. Замер в сквозном интеграционном тесте Tier 3 (47 заметок чертежа):
   $$\max |\Delta X| = 0.0000 \text{ мм}, \quad \max |\Delta Y| = 0.0000 \text{ мм}$$

### 3.7. Двухэтажные дроби материалов по ГОСТ 2.104

#### Реализация в `FormatEskdMaterialFB` (строки 50–109):
Формирование строки двухэтажной дроби сортамента и марки стали:
```csharp
// Прокат (Лист, Труба, Уголок) помещается внутрь числителя дроби <STACK>
// Ведущий пробел (" ") гарантирует корректность работы макроса MProp (InStr("<") == 2, Left$(str, 0) == "")
return string.Format(" <FONT size=1.8><FONT size=3.5><STACK size=1>{0}<OVER>{1}</STACK>", top, bottom);
```

Пример формируемой строки в свойстве `Материал_ФБ`:
```

```
Основная надпись чертежа SolidWorks корректно интерпретирует тег `<STACK>...<OVER>...</STACK>` и отображает классическую двухэтажную дробь с горизонтальной чертой деления.

## 4. Аудит безопасности и отказоустойчивости кодовой базы

1. **Принцип наименьших привилегий (Non-Admin Operation)**:
   - Вся регистрация COM-сервера, ветки автозагрузки `AddIns` и настройки пользовательского интерфейса CommandManager осуществляются в ветке `HKEY_CURRENT_USER`.
   - Надстройка и все макросы полностью работоспособны под стандартной доменной учетной записью без прав локального администратора.
2. **Отсутствие абсолютных жестких путей**:
   - В кодовой базе и реестровых файлах устранены все упоминания чужих профилей пользователей (`C:\Users\...`) и несуществующих дисков (`E:\Temp\...`).
   - Все пути к базам форматок, шаблонов и материалов вычисляются динамически относительно переменной `$ToolsRoot` при выполнении конфигуратора.
3. **Безопасная обработка исключений в COM-хуках**:
   - Все обработчики событий обернуты в блоки `try/catch`. Любая внештатная ситуация (например, поврежденная модель или отсутствие свойства) логируется в `%TEMP%\eskd_material_sync.log` без выброса модальных окон ошибок, блокирующих работу инженера.
4. **Режим подавления диалогов (Silent Background Mode)**:
   - Фоновые обработчики сохранения принимают флаг `isBackground = true`, подавляя графические интерфейсы и диалоги подтверждения.
