## 1. Назначение и участники

**Назначение.** Конструктор моделирует изделие в SolidWorks, а система берёт на себя рутину по ЕСКД и регламенту КТО: реквизиты основной надписи, материал и массу, файлы для производства, заявки в цеха, ревизии, выдачу и архив заказа. Всё, что система пишет в модели, совпадает с тем, что записал бы макрос MProp пакета SWPlus.

**Масштаб.** Пять конструкторов отдела металла, Synology NAS по SMB без PDM, SolidWorks 2025.

| Роль | Что делает в системе |
| :--- | :--- |
| Начальник КТО | правит справочник нормативов; выдаёт заказ в производство; закрывает заказ; утверждает изменения |
| Конструктор | моделирует; назначает материал и операции; формирует экспорт, проверку и СЗ на производство; выпускает ревизии |
| Куратор баз | ведёт эталоны `02_БАЗА` и библиотеку; делает снимки эталонов |
| Технолог | проверяет СЗ на производство и файлы ЧПУ |
| Администратор САПР | публикует инструментарий в сетевую папку |
| Цеха (заготовка, сварка, покраска, склад) | получают защищённую заявку и файлы; ничего не правят |

## 5. Функционал, который работает

### 5.1. Установка рабочего места

- Администратор публикует инструментарий: `Publish-EskdToolkit.ps1 -Target <сетевая папка>` — прогон тестов, сборка, копия без папок разработки, `toolkit_release.json` с версией.
- Конструктор запускает `Настройка_Рабочего_Места_SolidWorks.exe` из сетевой папки, без прав администратора. Окно само:
  - берёт путь к инструментарию из папки запуска — переезд папки не требует перенастройки;
  - направляет SolidWorks на шаблоны, форматки, библиотеку и профили в сетевой папке;
  - копирует надстройку и макросы SWPlus в `%LOCALAPPDATA%\ESKD\Toolkit`, сохраняя настройки макросов при обновлении;
  - прописывает в `Master.ini` путь к форматкам в сетевой папке;
  - ставит 9 кнопок SWPlus, шрифты ГОСТ, фамилию и организацию;
  - по флажкам — Drew (с корректной переустановкой другой сборки), блокировку выхода SolidWorks в интернет, русский язык Drew.
- Повторный запуск — обновление; автообновления нет (решение 14.09.2026).
- Подробно: руководство, часть II, §1; ТЗ-01; аудит сетевого развёртывания 14.09.2026.

### 5.2. Надстройка ЕСКД — реквизиты при сохранении

| Функция | Как работает |
| :--- | :--- |
| Обозначение и наименование | из имени файла `Обозначение Наименование.sldprt`, `Обозначение СБ Наименование.sldasm`; исполнения — по конфигурациям (ГОСТ 2.113); ручные значения не переписываются |
| Когда пишет | перед записью файла и после «Сохранить как»; открытие, переключение окон и сохранение чертежа ничего не меняют |
| Модель свойств | имена только из словаря SWPlus, уровни хранения как у MProp; «Применить» в MProp без правок ничего не меняет |
| Материал | штатный выбор из библиотеки ГОСТ; в каждую конфигурацию — `Материал_ФБ` (дробь для графы 3), `Материал_Таблица`, `Материал_Строка` (одна строка для ведомостей); если корпоративной библиотеки нет в настройках SolidWorks — предупреждение, запасной библиотеки нет |
| Масса | `Масса_Таблица` — живое выражение конфигурации; `Масса_ФБ` — с запятой и заданной точностью |
| Подписи | пустые «Конструктор», «Проверил» и др. заполняются из настроек |
| Сборки | код СБ в `Сборка1_ФБ`, «Сборочный чертёж» в `Сборка2_ФБ`, компоненты не обходятся |
| Защита покупных | изделия SProp, каталогов поставщиков и Toolbox не трогаются |
| Основная надпись | заметки не смещаются при сохранении (0,001 мм) |

### 5.3. Кнопки вкладки «ЕСКД» (сейчас)

| Кнопка | Что делает |
| :--- | :--- |
| Настройки ЕСКД | фамилии, организация, точность массы, флаги синхронизации |
| Синхронизировать | записать реквизиты активного документа без сохранения |
| Деталь БЧ | переключатель «чертёжная / безчертёжная»: `Формат` = БЧ, масса в примечании, запись для спецификации по ГОСТ Р 2.109-2023; повторное нажатие возвращает чертёжную; кнопка показывает текущее состояние |

### 5.4. Макросы SWPlus

MProp — свойства моделей; SProp — стандартные и покупные изделия; DProp — свойства чертежа и формата; SpecEditor — спецификации ГОСТ Р 2.106; RecordDimM — допуски; Roughness — шероховатость ГОСТ 2.309; TT — технические требования ГОСТ 2.316; Master — смена форматок; SaveAsPDF — PDF чертежей. Правила правки и проверки — руководство, часть II, §7а.

### 5.5. Утилиты

- `ESKD_Sync.exe /clean <файлы> [/apply] [/report отчёт.csv]` — очистка файлов, сохранённых надстройкой v5, пробный прогон и применение с резервной копией.
- `/reloadformats` — перезагрузка форматок в существующих чертежах (руководство, ч. II, §5.1).

### 6.1. Новые кнопки

| Кнопка | Кто | Документ | Что делает | Результат |
| :--- | :--- | :--- | :--- | :--- |
| Операции | конструктор | деталь, сборка | маршрут в свойство `Операции`; галочки расставлены по модели, конструктор подтверждает | свойство модели |
| Сделать независимым с чертежом | конструктор | сборка изделия | копия детали из базы под новым обозначением для всех выделенных экземпляров, копия чертежа с перепривязкой видов | модель и чертёж в `01_3D` |
| Экспорт для производства | конструктор | сборка, деталь | PDF цветной, все листы; DXF R2000 развёрток со слоем гибов `<Обозначение>_S1.5_<марка>_x<шт>`; IGS труб; ревизия у каждого документа своя; прежние файлы — в `_Аннулировано` | `02_PDF`, `03_ЧПУ`, отчёт |
| Проверить изделие | конструктор | сборка | ссылки, перестроение, материал, масса, чертёж или БЧ, файлы выдачи, операции; итог ГОТОВО / ЗАМЕЧАНИЯ / БРАК с контрольной суммой | `_Проверка_<дата>.txt` |
| СЗ на производство | конструктор | сборка | заявка в цеха по изделию (§6.3) | `СЗ_<Обозначение>.xlsx` |
| Новая ревизия | конструктор | деталь, сборка, чертёж | ревизия N+1 документа, таблица изменений в штампе, строка журнала, перевыпуск файлов | штамп, `Изменения.xlsx`, файлы `_ИзмN` |
| Снимок эталона | куратор баз | сборка эталона | копия в `_Версии\Изм<N>`, применяемость по открытым заказам | `_Версии`, `Изменения.xlsx` |
| Выдать в производство | начальник КТО | заказ | выбор изделий служебной записки и количества, цвета, проверка готовности, сводная заявка на заказ, копия комплекта | `04_ПРОИЗВОДСТВО\<заказ>` |
| Закрыть заказ | начальник КТО | заказ | Pack and Go, проверка копии, архив на `Y:`, заказ в `_Сдано` | `Y:\<год>\<заказ>` |

Каждая кнопка: серая с причиной, если недоступна; проверяет, что файлы не заняты; показывает отчёт и пишет его в файл; вызывается COM-методом для автотестов; пишет только в папки заказа, изделия, эталона, `04_ПРОИЗВОДСТВО`, `Y:`.

### 6.2. Новые свойства модели

| Свойство | Где | Кто пишет | Зачем |
| :--- | :--- | :--- | :--- |

### 6.3. СЗ на производство

**Форма** — по сводной заявке КТО 85_Т: пять листов A4 книжной, шапка (фирма, дата, № заявки, нач. КТО, изделие, шифр, тираж), таблица, ИТОГО, технологические указания участка, подписи. Книга и листы защищены паролем: цех не меняет столбцы, строки и текст. Реквизиты — на скрытом листе «Данные».

**Расцеховка — только по свойству `Операции`:**

| Операция | Лист | Что в строке |
| :--- | :--- | :--- |
| Лазерная резка листа, Лазерная резка трубы, Гибка | 1 Заготовка | деталь, сортамент, длина L, на 1 изделие, всего, операции |
| Сварная сборка, Механическая сборка | 2 Сварка | узел, операция, масса, количество |
| Покраска | 3 Покраска | окрашиваемый узел целиком, комплект цвета, изделий, всего, RAL |
| покупное изделие | 4 Комплектация | код 1С, номенклатура, ед. ОКЕИ, количество, назначение |
| — | 5 Списание | расход проката с раскроем хлыстов, КИМ, деловые обрезки, отход; краска по каждому RAL |

Правила: сварка и покраска идут параллельно по одним узлам (сварная сборка с «Покраска» — на листах 2 и 3); окраска берётся на верхнем отмеченном уровне, детали окрашиваемого узла на лист 3 не выводятся; детали сварного узла — заготовки на листе 1; крепёж механической сборки — на листе 4.

**Цвета — окно «Цвета покраски», модели не меняются:**

- «Цвет для всего» из выпадающего списка RAL — всё изделие или весь заказ одним цветом;
- «Разделить» на строке узла — новый комплект: количество и RAL; остаток в первом комплекте; комплектов сколько угодно;
- окрашиваемые детали разделённой сборки появляются в каждом комплекте, цвет выбирается напротив каждой (верх каркаса белый, низ синий);
- запись недоступна, пока нет цвета или не сходятся количества; назначение хранится в СЗ и подставляется снова;
- позже (ТЗ-03): заполнение таблицы языковой моделью по фразе, конструктор подтверждает.

**Раскрой хлыстов** — «первый подходящий по убыванию» по параметрам станка: торцовка в начале хлыста, рез после каждой детали, захват патрона в конце; остаток не короче делового — на склад, короче — в отход. Эталон расчёта — `09_Тесты/tools/tz02_norms.py`. На заявке 85_Т по новым нормативам: труба ø32×1,5 — 69 хлыстов вместо 82, 20×20×1,2 — 14 вместо 12.

**Окно перед записью:** реквизиты и тираж; цвета; нормативы станков из справочника с правкой только на этот заказ и сбросом; предварительный итог хлыстов и КИМ; список замечаний.

**На заказ** («Выдать в производство»): галочки изделий служебной записки, количество (можно меньше тиража), цвета по всем изделиям, одна сводная заявка той же формы, раскрой по всем деталям заказа сразу.

## 8. Разработка

### 8.1. Архитектура надстройки

| Слой | Содержимое | Правило |
| :--- | :--- | :--- |
| `Core/` | логика без SolidWorks: словарь, разбор имён, материалы, формат MProp; по ТЗ-02 — `Xlsx`, `Norms`, `Cutting`, `ProdNote`, `ExportNaming`, `ChangeLog`, `ChangeReasons`, `OrderNote`, `OrderMatcher`, `OrderNumbering` | покрыт юнит-тестами |
| `Sw/` | работа с SolidWorks: `PropertyWriter`, `SyncService`, `BchService`, `EventHub`; по ТЗ-02 — сервис на каждую кнопку | один сервис на кнопку |
| `SwAddin.cs` | команды вкладки, enable-методы, COM-методы | вкладка пересоздаётся при смене состава |
| Формы | `SettingsForm.cs`; по ТЗ-02 — окна «Операции», «СЗ на производство», «Цвета покраски», подготовки заказа | — |

**Правила кода:**

1. **К-1:** значение, записанное надстройкой, совпадает с записью MProp; «Применить» без правок ничего не меняет.
2. Запись свойств — только через `PropertyWriter`; имена — только из `PropertyDictionary` (тест ищет литералы).
3. Excel — через `System.IO.Packaging`, без сторонних библиотек и без Excel на ПК.
4. Кнопки пишут только в папки заказа, изделия, эталона, `04_ПРОИЗВОДСТВО`, `Y:`; в сетевую папку инструментария — никогда.
5. Геометрию, конфигурации и ссылки моделей не меняют, кроме «Сделать независимым» и перепривязки чертежа.
6. Макросы SWPlus не меняются без отдельного коммита и приёмки К-1.

### 8.2. Сборка и выпуск

- `build.ps1` — DLL и утилиты системным `csc.exe`; `build_manifest.json` с хешами.
- `Register-EskdAddin.ps1` — единственный модуль регистрации.
- Выпуск: тесты → `Publish-EskdToolkit.ps1` → повторный запуск окна настройки на ПК.

### 8.3. Ветки и коммиты

- `main` и `refactor/v6-eskd` — выпущенное; метки `v6.2-swplus-rc1…rc3`.
- `feature/tz02-eskd-buttons` — ТЗ-02; коммиты по кнопкам с трейлером соавторства.
- Отправка на GitHub и слияние — только по команде владельца. Папка `99_Архив` в git не попадает.

### 8.4. Автотесты

```
python 09_Тесты/run_tests.py static | unit | contract | e2e | full  [-k фильтр]
```

| Уровень | Что | SolidWorks |
| :--- | :--- | :---: |
| T0 static | репозиторий, словарь, библиотека, профиль реестра, установщик (в том числе установка из папки только для чтения), документация | нет |
| T1 unit | ядро C#: имена, разметка, БЧ, миграция; по ТЗ-02 — U01…U10 (справочник, раскрой, Excel, журнал, имена файлов) | нет |
| T2 contract | измеренная модель событий сохранения | да |
| E2E | группы P, M, B, D, S, R, I на фикстурах корпусов А и Б; по ТЗ-02 — E01…E09 | да |

Правила харнесса: SolidWorks поднимается, только если не запущен; диалоги файлов не используются; сохранения — внутри каталога прогона; настройки пользователя и реестр восстанавливаются; старые рабочие и архивные чертежи не открываются — только фикстуры. Отчёты — `08_Результаты_Тестирования/runs/<дата>/`. Известные дефекты — `09_Тесты/defects.json`.

Инструмент универсальный: проверка на тестовых сборках и копиях 89 типовых деталей, без подгонки под конкретное изделие. Заявка 85_Т используется только как набор длин с известным ответом для раскроя.
