## 🚀 Ключевые возможности

* **Реквизиты основной надписи (ГОСТ Р 2.104-2023) из имени файла**: `Обозначение Наименование.sldprt` и `Обозначение СБ Наименование.sldasm` дают обозначение, наименование и код сборки; исполнения — по именам конфигураций (ГОСТ 2.113). Значения, введённые вручную, не переписываются.
* **Одна модель свойств с SWPlus**: имена — из словаря SWPlus `MyProperties_1.ini`, уровни хранения — как у MProp; имён вне словаря надстройка не создаёт.
* **Запись только при сохранении**: реквизиты пишутся перед записью файла и после «Сохранить как»; открытие документов и переключение окон ничего не меняют, сохранение чертежа не пишет в модель.
* **Двухэтажная дробь материала и однострочная запись**: материал назначается штатно из библиотеки ГОСТ; при сохранении в графе 3 — форма и дробь «сортамент / марка», как у MProp, а в `Материал_Строка` — одна строка для сводной ведомости материалов по заказу.
* **Масса для графы 5 в каждой конфигурации**: `Масса_Таблица` — живое выражение массы конфигурации, как у MProp; `Масса_ФБ` — с запятой и заданной точностью, пересчёт при каждом сохранении; выражения MProp не переписываются.
* **Безчертёжные детали (БЧ)**: кнопка «Деталь БЧ» пишет «Формат» = БЧ, массу в «Примечание» и запись для спецификации по ГОСТ Р 2.109-2023; повторное нажатие восстанавливает прежние значения.
* **Защита стандартных и покупных изделий**: изделия SProp, каталогов поставщиков и Toolbox надстройка не трогает.
* **Форматки SWPlus по ГОСТ 2.301 и ГОСТ Р 2.104-2023**: 18 основных надписей форм 1 и 2а; заметки основной надписи не смещаются при сохранении.
* **Очистка файлов прежней версии**: `ESKD_Sync.exe /clean` — пробный прогон с отчётом CSV, применение с резервными копиями.
* **Развёртывание рабочего места одним батником**: реестр SolidWorks, пути к шаблонам и библиотекам, сборка и регистрация надстройки, шрифты ГОСТ, панели инструментов.
* **Автоматизация черчения Drw (Drew)**: модуль компоновки видов, масштабирования и расстановки размеров.

## ⚡ Быстрый старт (Развертывание в 1 клик)

### Системные требования
* **ОС**: Windows 10 / Windows 11 (x64).
* **САПР**: SolidWorks 2018, 2019, 2020, 2021, 2022, 2023, 2024, **2025 SP0+**. Полная автоматическая настройка рабочего места верифицирована на SolidWorks 2025; скрипт развертывания поддерживает автодетект установленной версии (2018–2025), корпоративный реестровый профиль поставляется для SW2025.
* **Среда выполнения**: Microsoft .NET Framework 4.8 (или 4.0 Client Profile), Windows PowerShell 5.1+.
* **Права доступа**: Права локального Администратора рекомендуются для разовой системной регистрации надстройки и шрифтов. Основная функциональность надстройки и макросов регистрируется в профиле текущего пользователя (`HKCU`) и работает **без прав администратора**.

### Порядок установки на новое рабочее место (один клик)

1. Склонируйте/скопируйте репозиторий на целевую машину (папка `_Инструменты_Конструктора`, диск любой).
2. **Двойной клик по `УСТАНОВИТЬ_ЕСКД.bat` в корне репозитория** — батник сам запросит права администратора (UAC), закроет SolidWorks (с подтверждением) и выполнит весь конвейер, включая сборку надстройки из исходников.
3. Ручной эквивалент (консоль PowerShell от имени Администратора):
   ```powershell
   powershell -ExecutionPolicy Bypass -File ".\01_Настройки_SolidWorks\Setup_Workstation_SolidWorks.ps1"
   ```
4. Скрипт выполнит:
   - Импорт корпоративных настроек интерфейса SolidWorks 2025 (`.reg`);
   - Установку чертежных шрифтов ГОСТ тип A и тип B с автоматическим выбором режима: системная установка в каталог Windows Fonts (HKLM, требуется администратор) или пользовательская (HKCU, `%LOCALAPPDATA%\Microsoft\Windows\Fonts`) с уведомлением `WM_FONTCHANGE`;
   - Привязку путей поиска к форматам листов (`.slddrt`), шаблонам (`.prtdot`, `.drwdot`) и библиотеке материалов (`.sldmat`);
   - Сборку и регистрацию COM-надстройки **ЕСКД v6** в SolidWorks AddIns и автозапуске (вкладку **«ЕСКД»** для деталей, сборок и чертежей надстройка создаёт при каждом старте);
   - Закрепление 9 кнопок макросов пакета **SWPlus** в верхней панели быстрого доступа (QAT);
   - Активацию безопасного графического режима (исключающего черный экран в SolidWorks 2025);
   - Интеграцию модуля автоматизации черчения **Drw (Drew)**.
5. Запустите **SolidWorks 2025**. Убедитесь, что на панели CommandManager присутствует вкладка «ЕСКД», а в верхней строке — кнопки SWPlus.

## 🏛️ Архитектура программного комплекса

### 1. Нативная надстройка ESKD Material Sync (C# .NET)
Каталог: `03_Макросы_и_Плагины/ESKD_Material_Sync_Addin/`

* **Назначение**: ядро автоматизации v6. Реквизиты пишутся перед сохранением (`FileSaveNotify`) и после «Сохранить как»; открытие и переключение окон ничего не меняют. Имена свойств — словарь SWPlus, уровни хранения — как у MProp; дробь материала и масса для основной надписи, кнопка «Деталь БЧ».
* **Ключевые модули**:
  - `Core/`: словарь SWPlus, разбор имени файла, разметка граф, библиотека материалов, журнал (без SolidWorks, покрыты юнит-тестами);
  - `Sw/`: `PropertyWriter` — единственная точка записи свойств, `SyncService`, `EventHub`, `BchService`;
  - `SettingsForm.cs`: окно настроек надстройки (фамилия, организация, точность массы);
  - `build.ps1`: сборка DLL и утилит системным `csc.exe` (Visual Studio не нужна) и `build_manifest.json` с хешами;
  - `Register-EskdAddin.ps1`: единственный модуль регистрации — его используют Setup, `register_eskd.ps1`, `build_and_register.ps1`, `unregister.ps1` и исходник конфигуратора.
* **Автономные утилиты**:
  - `ESKD.exe`: окно настроек; `ESKD_Sync.exe`: синхронизация активного документа SolidWorks;
  - `ESKD_Sync.exe /clean <файлы и каталоги> [/apply] [/report отчёт.csv]`: очистка файлов, сохранённых надстройкой v5.
    Без `/apply` — только отчёт CSV (файл, уровень, имя, действие, было, стало, причина). С `/apply` исходники копируются
    в `_ESKD_backup_<дата>` рядом с первым каталогом, затем удаляются 21 лишнее имя v5; значения алиасов переносятся
    в пустые «Конструктор» (общие), «Проверил» и «Контора» (конфигурации); статичные «Масса» и «Материал»
    возвращаются к живым выражениям, «Формат» — кириллицей. Повторный запуск изменений не находит.
    Нужен запущенный SolidWorks; открытые в нём документы пропускаются.

## 📐 Правила и стандарты автоматизации ЕСКД

Нормативное описание — разделы 2–4 части I [руководства](06_Документация/РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ_И_АДМИНИСТРАТОРА.md).

### 1. Модель свойств и связь основной надписи с моделью
Заметки форматок SWPlus связаны со свойствами модели через `$PRPSHEET`:
* графа 1 — `Наименование_ФБ` (вторая строка у сборочного чертежа — `Сборка2_ФБ`);
* графа 2 — `$PRPSHEET:"Обозначение"$PRPSHEET:"Сборка1_ФБ"`;
* графа 3 — `Материал_ФБ`, графа 5 — `Масса_ФБ`, графа 9 — `Контора`;
* строки подписей — `Конструктор`, `Проверил`, `Техконтроль`, `Нормоконтроль`, `Утвердил`.

Имена берутся из словаря SWPlus `SpecEditor/MyProperties_1.ini`, общий для надстройки, MProp и SpecEditor. Уровни
хранения — как у MProp: `Обозначение` — общие и конфигурации; `Наименование`, `Наименование_ФБ`, `Конструктор` —
общие; `Проверил`, `Контора`, `Сборка1_ФБ`, `Сборка2_ФБ`, материал и масса — конфигурации.

> [!IMPORTANT]
> `$PRPSHEET` читает свойства модели в конфигурации вида, а не свойства файла `.slddrw`; значение конфигурации
> закрывает общее значение с тем же именем. Сохранение чертежа ничего не пишет ни в чертёж, ни в модель: чтобы
> обновить основную надпись, сохраните модель.

### 2. Когда надстройка пишет реквизиты
* **«Сохранить»** — перед записью файла: обозначение и наименование по имени файла, пустые подписи, материал, масса.
* **Первое сохранение и «Сохранить как»** — после записи: реквизиты по новому имени и одно пересохранение.
* **Выбор материала** — дробь сразу после закрытия команды.
* **Открытие, переключение окон, сохранение чертежа** — ничего.

Производные значения (пустые, выражения шаблона, прежнее имя файла) переписываются, ручные — нет.

### 3. Двухэтажная дробь материала и однострочная запись
Конструктор назначает материал штатно из «Библиотека_Материалов_ГОСТ» и сохраняет деталь. Надстройка копирует поля
библиотеки в каждую конфигурацию:
* `Материал_ФБ` — графа 3: форма перед дробью, над чертой сортамент, под чертой марка
  (`<FONT size=1.8> <FONT size=3.5>Лист <STACK size=1>Б-ПН-НО-4,0 ГОСТ 19903-2015<OVER>Ст3сп ГОСТ 14637-89</STACK>`);
* `Материал_Таблица` — то же без шрифта, в формате, который читает MProp;
* `Материал_Строка` — `Лист Б-ПН-НО-4,0 ГОСТ 19903-2015 / Ст3сп ГОСТ 14637-89`, одна строка для сводной ведомости материалов.

Конфигурация без материала ничего не получает; значения, введённые в MProp вручную, остаются. Графу 3 в PDF чертежа
проверяет тест P15.

### 4. Защита стандартных и покупных изделий (SProp / Toolbox)
Надстройка ничего не пишет в документ, если выполняется любое условие:
1. `Раздел` содержит «стандартн», «прочи», «покупн», «материал» или начинается с «ЭМ-»;
2. `IsFastener` = 1 (true, да), либо заполнено одно из `Наименование_ВП`, `Поставщик`, `Код_Продукции`, `Обозначение_ДНП`, `Справочный_номер_ВП`;
3. файл лежит в каталоге `\toolbox\` или `SOLIDWORKS Data`.

### 5. Сборки: код документа без обхода компонентов
У сборки `ПРТИ.468211.100 СБ Рама.sldasm` обозначение хранится без кода, код СБ — в `Сборка1_ФБ` каждой конфигурации,
`Сборка2_ФБ` = «Сборочный чертёж», масса — масса узла. Компоненты сборки при сохранении не обходятся.

### 6. Нулевое смещение заметок основной надписи
Сохранение чертежа не сдвигает заметки основной надписи: координаты до и после сохранения совпадают с точностью
0,001 мм (тест D04). Геометрию форматок по ГОСТ 2.301 и ГОСТ Р 2.104-2023 проверяет тест D09.

## 🧪 Автоматизированное тестирование

Автотесты лежат в `09_Тесты/` и запускаются одним раннером:

```powershell
python .\09_Тесты\run_tests.py static     # T0: репозиторий, словарь, библиотека материалов, профиль .reg, регистрация
python .\09_Тесты\run_tests.py unit       # T1: юнит-тесты ядра C# (разбор имён, разметка, БЧ, миграция v5)
python .\09_Тесты\run_tests.py contract   # T2: измеренная модель событий сохранения SolidWorks
python .\09_Тесты\run_tests.py e2e        # сценарии на фикстурах корпусов А и Б в собственной сессии SolidWorks
python .\09_Тесты\run_tests.py full       # всё вместе; фильтр по имени — ключ -k
```

| Группа | Что проверяет |
|---|---|
| P — персистентность | первое сохранение, «Сохранить как» и копии, открытие и переключение окон без записи, смена материала |
| M — модель свойств | только словарные имена SWPlus на уровнях MProp, «чужие» подписи и ручные обозначения, исполнения, живые масса и материал |
| B — безчертёжные детали | «Деталь БЧ»: формат, масса в примечании, запись по ГОСТ Р 2.109-2023, снятие признака |
| D — чертежи | тексты и геометрия граф основной надписи (ГОСТ Р 2.104-2023), форматки по ГОСТ 2.301 и ГОСТ Р 2.104-2023, нулевое смещение заметок, чертёж не пишет в модель |
| S — спецификация | формы SpecEditor и основные надписи не печатают служебную заметку «Файл:» |
| R — корпуса и миграция | golden master: отличия от снимка поведения v5 объяснены правилами `baseline/allowed_diffs.json`; `ESKD_Sync.exe /clean` на файлах, сохранённых надстройкой v5 |
| I — установка | шаблоны документов, перезагрузка надстройки |

Каждый прогон пишет `junit.xml` и `report.md` в `08_Результаты_Тестирования/runs/<дата_время>/` вместе с журналом
событий и копиями файлов. Известные дефекты ведутся в `09_Тесты/defects.json`: тест открытого дефекта ожидаемо
падает, а неожиданный успех подсказывает закрыть дефект.

Фикстуры повторяют работу конструктора: у деталей из проката — сортамент из корпоративной библиотеки. Корпус А собирает
`09_Тесты/fixtures/build_fixtures.py`. Корпус Б — реальные файлы архива: рабочие сценарии идут на копиях с сортаментом из
библиотеки (`fixtures/B`, `fixtures/build_corpus_b.py`), исходники в `08_Результаты_Тестирования` открывает только
golden master R01. Материалы фикстур проверяют T0 и I07.

Правила безопасности харнесса: SolidWorks поднимается только если он не запущен; диалоги файлов не используются;
все сохранения — внутри каталога прогона; параметры ESKD_Settings пользователя восстанавливаются после прогона.
Прежний набор Tier 1–4 (надстройка v5) хранится для справки в `09_Тесты/legacy/`.

## ❓ Часто задаваемые вопросы и устранение неполадок (FAQ / Troubleshooting)

### 1. После установки не видна вкладка «ЕСКД» в CommandManager
* **Причина**: SolidWorks при закрытии может перезаписывать ветку реестра CommandManager своим кэшем из оперативной памяти.
* **Решение**:
  1. Закройте SolidWorks.
  2. Запустите скрипт перерегистрации:
     ```powershell
     powershell -ExecutionPolicy Bypass -File ".\03_Макросы_и_Плагины\ESKD_Material_Sync_Addin\register_eskd.ps1"
     ```
  3. Запустите SolidWorks. Если вкладка все еще скрыта, щелкните правой кнопкой мыши по любой вкладке CommandManager и включите галочку напротив **«ЕСКД»**.
  4. Загружена ли надстройка, видно в журнале `%TEMP%\eskd_material_sync.log` — строка `=== ConnectToSW v6.0.0`. Загруженная надстройка создаёт вкладку программно при каждом старте, поэтому кэш CommandManager в реестре на неё не влияет.

### 2. Кнопки макросов SWPlus в верхней панели QAT отображаются серыми значками
* **Причина**: Не совпадает сопоставление ID кнопок меню (`Menu Customizations`) и панели быстрого доступа (`GB0`).
* **Решение**: Запустите `Setup_Workstation_SolidWorks.ps1`. Скрипт принудительно сопоставляет кнопки с системными ID `33639..33647` и очищает кэш изменений тулбаров.

### 3. Черный экран рабочей области в SolidWorks 2025
* **Причина**: Несовместимость видеокарты или драйвера с новым графическим конвейером SolidWorks (*Enhanced Graphics Performance*).
* **Решение**: Скрипт развертывания автоматически отключает данный режим в реестре:
  ```powershell
  Set-ItemProperty -Path "HKCU:\Software\SolidWorks\SOLIDWORKS 2025\Performance" -Name "Use Performance Pipeline 2020" -Value 0
  ```

### 4. Как пересобрать надстройку после изменения исходного кода C#?
Запустите скрипт компиляции:
```powershell
powershell -ExecutionPolicy Bypass -File ".\03_Макросы_и_Плагины\ESKD_Material_Sync_Addin\build_and_register.ps1"
```
Скрипт запускает `build.ps1` (системный `csc.exe` .NET Framework 4: `ESKD_Material_Sync_v5.dll`, `ESKD.exe`, `ESKD_Sync.exe`, `build_manifest.json`) и регистрирует надстройку модулем `Register-EskdAddin.ps1`. Команды выполняются из корня репозитория.
